## Что проверить

- **Docker.** Из чистого клона выполните `docker compose up --build`. Проверьте `http://localhost:8000` и `http://localhost:8000/api/health`. Ожидается источник `synthetic` и каталог из 23 материалов. Проверьте оба задания `docker-check` в GitHub Actions. Docker-прогон требуется подтвердить запуском.
- **Ранжирование.** Выберите P01 и P02. У P01 первые три кода M01, M07, M04. У P02 первым стоит курс для растущего бизнеса. Подбор по теме одинаков для P01 и P02, персональная выдача различается. После «Отметить изученным» у первой карточки P01 подборка обновляется.
- **Пограничные состояния.** Пустая форма даёт стартовую подборку. P05 предлагает уточнить тему, P04 сообщает об отсутствии материалов. При недоступном API повтор сохраняет ввод. У карточки без ссылки отсутствует кнопка перехода.
- **Дизайн.** Сверьте 390 и 1120 px, табуляцию, видимый фокус, отсутствие горизонтального скролла и различие между уточнением и ошибкой. Ориентиры — [UI-кит](../design/ui-kit.md) и [референс](design.md).
- **Данные.** Сначала повторите демо на [тестовом каталоге](../backend/data/catalog.synthetic.json). Затем подключите разрешённую копию по [инструкции](data.md). В `/api/health` проверьте источник `sqlite`, покрытие и признаки, для которых данных не хватает.
- **Презентация.** Сверьте по [плану слайдов](presentation.md) команду и адрес на первом слайде, маршрут демо, источник каждой цифры и ограничения оценки.

В замечании укажите сценарий, ожидаемое и фактическое поведение, версию и команду запуска. Ветку открывайте от актуального `main`.
