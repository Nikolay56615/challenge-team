# Локальная выгрузка образовательной платформы

`catalog.sqlite3` — производная SQLite-копия предоставленной выгрузки для работы над кейсом. В ней 61 таблица и 101 925 строк. База открывается без отдельного сервера. Для анализа открывай её в режиме чтения.

## Что есть в базе

| Назначение | Таблицы и объём |
| --- | --- |
| Каталог | `Articles` — 855, `Courses` — 37, `Lessons` — 508, `Documents` — 247, `Webinars` — 19, `Podcasts` — 8, `Glossary` — 351, `Calculators` — 7 |
| Темы, теги и отрасли | `Topics`, `Tags`, `Industries`, `ArticleSubjects` и связующие таблицы `ContentSettingsTopics`, `ContentSettingsTags`, `ContentSettingsIndustries` |
| Метаданные материалов | `ContentSettings`, `Statuses`, `CourseTypes`, `LessonTypes`, `DocumentTypes` и другие справочники |
| Связи материалов | `RecommendedItems` — 3 996 связей. `CourseLessonBindings` и `DocumentBindings` связывают курсы с уроками и документы друг с другом |
| Активность | `CourseUserBindings` — 10 050, `CourseUserLessonBindings` — 21 489, `UserRatings` — 8 343, `UserRatingTagsBindings` — 7 026 |
| Структура содержимого | `ArticleEmbedItems`, `LessonEmbedItems`, `DocumentEmbedItems`, `GlossaryEmbedItems` и другие таблицы блоков содержат идентификаторы, тип и порядок. Тексты и параметры блоков исключены |

## Как пользоваться

- Имена таблиц и сохранённых полей соответствуют техническим именам источника. Типы в SQLite приведены к `TEXT`, `INTEGER` и `REAL`. Логические поля хранятся как `0` и `1`, пропуски — как `NULL`.
- `ContentSettings.EntityId` связывает метаданные с `Id` в `Articles`, `Courses`, `Documents`, `Webinars` и `Podcasts`. `ContentSettings.Id` используется в таблицах связей с темами, тегами и отраслями. Для статей также есть `Articles.SubjectId` и `ArticleSubjects.Id`.
- Для доступа к курсам используй `Courses.TypeId` вместе с `CourseTypes.Id` и проверяй `IsClosed` и статус. `HasListedPrice` показывает наличие положительной цены в исходном поле `Cost`. Пропуск цены сам по себе не означает бесплатный доступ.
- `CourseUserLessonBindings.CourseUserId` указывает на `CourseUserBindings.Id`. `UserId` заменён согласованно. `EventOrder` — относительный порядок по времени создания среди трёх таблиц активности для одного пользователя. Совпавшие моменты получают одинаковый порядок. `NULL` означает, что событие не удалось связать с пользователем. Календарные даты и интервалы по этому полю восстановить нельзя.
- `EntityTypeId` и `ItemTypeId` в полиморфных связях — технические коды. Определяй целевую таблицу по фактическому совпадению идентификаторов и роли связи. Одинаковый код в разных таблицах сам по себе не устанавливает одинаковую семантику.

Пример проверки тем статьи по её псевдонимному `Id`:

```sql
SELECT DISTINCT t.Title
FROM Articles AS a
JOIN ContentSettings AS c ON c.EntityId = a.Id
JOIN ContentSettingsTopics AS ct ON ct.ContentSettingsId = c.Id
JOIN Topics AS t ON t.Id = ct.TopicId
WHERE a.Id = ?
ORDER BY t.Title;
```

## Границы копии

Идентификаторы заменены последовательно, поэтому сохранённые ссылки можно соединять. Общие темы, теги, статусы и типы оставлены. Фирменные и неоднозначные ярлыки заменены, а материалам, авторам и экспертам присвоены нейтральные подписи. Из копии исключены ссылки, персональные поля, исходные названия и описания материалов, свободный текст, полные тексты уроков, исходные даты, точные цены и служебная история миграций.

На этой базе можно сравнивать рекомендации по категориям и структуре взаимодействий. Полнотекстовый поиск, переходы на исходные страницы, календарный анализ и подтверждение влияния на реальные покупки требуют отдельных разрешённых данных. Для демонстрации используй вымышленные профили. Храни базу локально и исключай из Git, Docker-контекста и общедоступных материалов. При локальном запуске передавай путь к файлу или монтируй его только для чтения.

## Признаки из названий и описаний

`catalog-signals.sqlite3` дополняет каталог. Таблица `MaterialSignals` содержит 536 связей с 36 нейтральными признаками для 436 из 1 166 материалов. Например, различаются выбор налогового режима, налоговая отчётность и бухгалтерский учёт. Метки извлечены локально по словарю выражений. Исходные фразы, описания и ссылки в файл не вошли.

| Поле | Назначение |
| --- | --- |
| `MaterialId` | Псевдонимный ключ. Соединяй с `ContentSettings.EntityId` |
| `MaterialFormat` | `article`, `course`, `document`, `webinar` или `podcast` |
| `SignalCode`, `SignalLabel` | Машинный код и нейтральное название признака |
| `MatchedTitle`, `MatchedDescription` | Совпадение со словарём в исходном названии или описании. Значения `0` и `1` |

Формируй признаки запроса по тому же набору понятий. Используй совпадение в названии как более сильный сигнал. Совпадение только в описании может быть случайным упоминанием. Для материалов без меток продолжай подбор по темам, тегам и истории. Если показываешь метку пользователю, обозначь её как тему материала. Метка сама по себе не подтверждает конкретный результат обучения.

Сравни порядок выдачи с метками и без них на одинаковых профилях и запросах. Добавь несколько пар в рамках одной темы, например запрос о выборе налогового режима и запрос о сдаче декларации. Попроси проверяющего оценить уместность карточек по материалам, которые он вправе читать. Покрытие метками и смена порядка сами по себе не измеряют качество рекомендаций.
