Краткая версия плана для комплекта. Разделы 1–9 и 13 пронумерованы как в рабочем плане автора, поэтому ссылки в комментариях кода вида «docs/plan.md, 3.2», «раздел 9, решение 2026-11-11» или «раздел 13» ведут в нужное место. Раздел 13 описывает ленту по профилю, главный сценарий прототипа. Раздел 10 перечисляет ограничения. Раздел 11 описывает кандидатов развития и вопросы, которые ждут решения пользователя. Компоненты и токены интерфейса описаны в [UI-ките](ui-kit.md), запуск и проверки — в [README](../README.md). Рабочие протоколы автора в комплект не входят, их итоги пересказаны здесь. Коды вида W06, R05 и D09 в комментариях кода — номера кандидатов улучшений, их перечень со статусами — в конце раздела 11. Состояние на 15 ноября 2026 года.

Статусы в документе: «требование» — из условия, «наблюдение» — проверено на обезличенной копии выгрузки платформы, «допущение» — принято до подтверждения, «решение» — выбор с основанием.

## 1. Исходные условия

### 1.1 Подтверждено

- Прототип закрывает трек 1. Главный сценарий: лента рекомендаций по истории клиента с видимым составом оценки (раздел 13). Дополнительный путь: предприниматель описывает задачу, при желании указывает стадию бизнеса, опыт, формат и сферу; сервис возвращает упорядоченный список материалов с причиной и следующим шагом и сравнивает его с простым подбором по теме.
- Для разработки использовалась обезличенная копия выгрузки платформы в SQLite: каталог, справочники, записи на курсы и 36 нейтральных признаков из названий и описаний. В копии нет исходных названий, описаний, ссылок, дат и цен. Копия в комплект не входит.
- Запуск проверяется через Docker Compose одной командой, других способов сборки нет (4.5).

### 1.2 Допущения

- Демонстрация подбора по задаче идёт на размеченном синтетическом каталоге из 23 материалов с теми же каноническими полями, что у загрузчика копии. Лента по профилю показывается на расширенном синтетическом каталоге из 166 материалов, в который размеченный входит без изменений (13.3). Копия нужна только для проверки загрузчика, покрытия признаков и офлайн-оценки по истории курсов.
- Порядок событий пользователя известен, календарные даты и интервалы — нет. Свежесть материалов не вычисляется.
- Прототип запускается локально. Публичное развёртывание не планируется.
- Внешние LLM и API не используются. Подбор детерминирован и работает без сети.

### 2.7 Как и почему должна измениться выдача

P01 и P02 задают одну тему. Подбор по теме видит только её и выдаёт обоим одинаковый список в порядке популярности. Персональный подбор меняет порядок по стадии, уровню, формату, сфере, признакам и истории.

| Позиция | По теме, P01 и P02 | Персональный, P01 | Персональный, P02 |
| --- | --- | --- | --- |
| 1 | M03 шаблон контент-плана | M01 чек-лист: стадия, уровень, сфера, 15 минут | M02 курс для растущего бизнеса: признак, стадия, уровень, формат |
| 2 | M02 платный продвинутый курс | M07 видео | M05 вебинар без ссылки |
| 3 | M01 чек-лист | M04 статья | M06 шаблон расчёта |
| 4 | M07 видео | M08 платный вводный курс | M08 вводный курс |
| 5 | M05 платный вебинар | M03 шаблон | M07 видео, «вы уже открывали» |

Для P01 наверх выходят короткие вводные бесплатные материалы. Для P02 продвинутый курс получает максимум по признаку, формату и уровню, пройденный шаблон уходит в конец с пометкой. Подбор по теме ставит пройденный шаблон на первое место — наглядный дефект простого метода. P06 поднимает продолжения просмотренного чек-листа, P08 ставит начатый курс первым, P10 поднимает материалы о налоговой отчётности выше статьи о выборе режима. При пустой задаче P11 получает M03, L02, M02, A03, M01 со статусом `weak` и вопросом «Уточните тему». P12 получает стартовую подборку со статусом `cold`, как P03.

### 2.8 Загрузка из SQLite и подмена источника

1. Источник переключает `CATALOG_SOURCE`: `synthetic`, `sqlite`, `file`. Копия открывается только на чтение и в образ не входит.
2. Запросы к копии и файл соответствия `mapping.example.yaml` задают группы тем, служебные метки, разбор длительности и коды событий. Для другой выгрузки меняется файл, а не код.
3. Загрузчик пишет сводку покрытия агрегатами; строки данных в журнал не попадают.
4. Отсутствующее поле отключает признак и его фразу в причине.
5. Тесты на профилях формулируются через свойства выдачи и переживают смену источника; для синтетики проверяется точный порядок 2.7.
6. Реальные события используются в офлайн-оценке 3.7, а при локальном запуске на копии ещё и как счётчики пар курсов для «похожих курсов».

## 3. Подбор и ранжирование

### 3.1 Подбор по теме

Запрос нормализуется, слова усекаются до основ по словарю тем. Кандидаты — доступные материалы совпавшей темы в порядке популярности. Причина у всех одна: «Совпадает тема «…»». Понятия признаков этот метод не различает. Остаётся в коде как `method=baseline` и используется в сравнении.

### 3.2 Персональный подбор: правила с признаками профиля

Конвейер: фильтр допустимости → отбор кандидатов → оценка признаков → правило разнообразия → разрешение равенств → статус выдачи → причины и следующий шаг. Фильтр допустимости оставляет только доступные материалы. Из дубликатов, то есть материалов с одинаковыми названием и форматом, он оставляет самый популярный, а купленный материал убирает вместе со всеми копиями. Кандидаты — материалы распознанных тем; явно выбранная тема имеет приоритет. Задача без темы, но с понятием признака («Какую CRM выбрать») собирает материалы с этим признаком из любых тем.

| Признак | Источник | Вклад | Нейтральность |
| --- | --- | --- | --- |
| Тема | Словарь тем, явный выбор | +3,0 | Без темы — кандидаты по понятию или стартовая подборка |
| Признак из текста | Понятия из 36 кодов в запросе и `signals` материала | +2,0 при силе 2, +1,0 при силе 1; не более одного | 0 при отсутствии |
| Стадия | Чип или подсказка из текста | +2,0 за чип, +1,0 за подсказку | 0, если неизвестна |
| Уровень | Опыт → уровень | +2,0 точное, +1,0 смежный; подсказка +1,0 | 0, если неизвестен |
| Сфера | Список или синоним в тексте | +1,0 | 0 без сфер у материала |
| Формат | Чип или подсказка | +1,5 за чип, +1,0 за подсказку | 0 без предпочтения |
| Усилие | До 30 минут при признаках новичка | +0,5 | 0 иначе |
| Продолжение | Материал в `recommended_next` последнего события истории | +1,5 | 0 без истории |
| Начатый курс | Событие `start` | +2,0, пометка «В процессе» | |
| Просмотрено | Событие `view` | −1,5, пометка «Вы уже открывали» | |
| Пройдено | Событие `complete` | −4,0, пометка «Пройдено» | |
| Тема истории | Темы материалов истории; только при подборе по истории (3.4) | +0,1, вложенный выбор на O1 (3.7) | 0 при задаче с текстом, выбранной теме и вне подбора по истории |
| Похожие курсы | Пары совместных записей; только курсы и только при пустой задаче | 3,0 × min(1, Σ N/M) по курсам истории: N — слушатели обоих курсов, M — слушатели курса истории. Пара учитывается при N не ниже `PAIRS_MIN_SUPPORT`, по умолчанию 10, и M не меньше 10 | 0 без пар, без курса в истории, при задаче с текстом и для материалов из истории |

Правило разнообразия: в пятёрке не больше трёх материалов одного формата, если у другого формата есть кандидат с оценкой не ниже лидера минус 2,0. Равенства разрешаются по нормированной популярности, затем по коду. Веса — гипотеза прототипа; тесты проверяют порядок на профилях, а не числа. Оба веса пилота тоже гипотезы. Вес темы истории в продукте равен 0,1: это значение вместо прежнего 1,0 дал вложенный выбор на офлайн-оценке (3.7, R33). Недоступный курс истории передаёт вес доступным соседям, а сам не показывается.

### 3.3 Почему выбраны правила

| Критерий | По теме | Правила с признаками | Семантический поиск | Модель на событиях |
| --- | --- | --- | --- | --- |
| Нужные данные | Тема | Темы, признаки, стадия, уровень, сфера, формат, история | Тексты материалов; в копии их нет | Журнал событий; только курсы |
| Объяснимость | Одна фраза | Каждый вклад даёт фразу | Сходство без причины | Слабая |
| Проверяемость | Да | Детерминировано, на синтетике и копии | Нет текстов | Офлайн по 1 562 пользователям |

Решение: правила с признаками. Модель на событиях применима только к курсам: она прошла офлайн-проверку (3.7), и после неё пользователь решил включить её пилотом как признак «похожие курсы» на заранее рассчитанных парах совместных записей (раздел 9, решение 2026-11-11).

### 3.4 Холодный старт

| Ситуация | Что делает система | Статус |
| --- | --- | --- |
| Пустая задача и анкета | Стартовая подборка: самый популярный вводный бесплатный материал по каждой теме; вопрос «С чего хотите начать?» | `cold` |
| Есть задача, нет анкеты | Распознавание темы, признаков и подсказок; строка состояния называет допущения | `strong` или `weak` |
| Задача и часть анкеты | Признаки включаются по мере заполнения | `strong` |
| Есть история | Начатый курс поднимается, просмотренное и пройденное понижается, работает продолжение | `strong` |
| Пустая задача, есть история | Подбор по истории в персональном методе, если у курса истории, доступного или нет, есть загруженная пара от порога с допустимым курсом вне истории, а у самого курса не меньше 10 слушателей. Кандидаты — материалы тем истории и связанные парой курсы, в том числе других тем. Выдача идёт с уточнением темы и без маршрута. Без такой пары остаётся стартовая подборка, даже если в истории есть начатый материал. Явно выбранная тема даёт обычный подбор по теме, её курсы получают вклад похожих курсов | `weak`; без пары от порога `cold`; с выбранной темой `strong` |

Анкета необязательна на всех шагах. В реальном каталоге вводный уровень размечен только у курсов, поэтому стартовая подборка берёт по теме самый популярный открытый материал со стадией «Старт бизнеса» или без стадии. Продвинутые материалы в неё не попадают.

### 3.5 Слабое совпадение, неоднозначность, пробелы

| Статус | Условие | Поведение |
| --- | --- | --- |
| `strong` | Явная тема с материалами, одна найденная тема, понятие без темы или узкий запрос с совпадением в названии | Выдача без уточнения |
| `weak` | Несколько тем с материалами, неподтверждённый признак или подбор по истории при пустой задаче (3.4) | Выдача плюс уточнение темы. При подборе по истории вопрос «Уточните тему», темы истории в вариантах первыми, маршрута нет |
| `none` | Задача есть, кандидатов нет | Сообщение о пробеле и выбор темы; стартовая подборка при наличии вводных материалов |
| `cold` | Пустая задача без выбранной темы, если подбор по истории не включился (3.4) | Вопрос о цели и выбор темы, стартовая подборка |
| `empty` | Нет вводных материалов и доступных тем | Сообщение и предложение изменить запрос |

Для узких запросов о лицензировании, алкоголе, сертификации и визах все распознанные признаки должны совпасть в одном названии. Уточнение — объект `clarification` с вопросом, полем и вариантами; выбор варианта повторяет запрос с заполненным полем, форма не очищается.

### 3.6 Причина и следующий шаг

Причина собирается из признаков с положительным вкладом, отсортированных по вкладу: две–три фразы, до 180 символов. Каждая фраза называет признак, который фактически повлиял на оценку; признак с наибольшим вкладом, кроме темы, назван всегда. Пометки истории выводятся бейджами. Это свойство проверяют тесты `test_reasons.py`, `test_explain_faithfulness.py` и `test_history_mode.py`: P01–P12, сетка из 400 анкет, выборка из 300 анкет пилота и 1 500 пустых задач с историей. Цитату D01 тест сверяет с задачей: она состоит из слов задачи в том же порядке и сама находит тот же признак. На сетке из 400 анкет в каждой причине столько же фраз, сколько без цитат.

| Признак | Шаблон фразы |
| --- | --- |
| Тема | «Тема «{тема}» совпадает с задачей». Если тему выбрали в уточнении, а задача её не называет: «Вы выбрали тему «{тема}»» |
| Признак из текста | «В задаче вы назвали «{слова задачи}» — материал о теме «{подпись признака}»» (D01). Цитата — слова задачи, по которым найден признак, в написании пользователя, до 30 символов; если задача называет понятие, цитируются слова понятия. Если слов признака в задаче нет или цитата вытеснила бы другую фразу: «Материал о теме «{подпись признака}»» |
| Стадия, чип | «Подходит для стадии «{стадия}»» |
| Стадия, подсказка | «Похоже, вы на старте — материал рассчитан на это» |
| Уровень, смежный | «На шаг глубже вашего уровня — пригодится как продолжение» |
| Сфера | «Подходит для сферы «{сфера}»» |
| Стадия из чипа и сфера вместе | «Подходит для стадии «{стадия}» и сферы «{сфера}»» |
| Продолжение | «Продолжает материал «{название}» из вашей истории» |
| Начатый курс | «Вы начали этот курс — продолжите с текущего урока» |
| Тема истории, пилот | «Тема из вашей истории: «{тема}»» — только при подборе по истории |
| Похожие курсы, пилот | «Этот курс выбрали {N} из {M} слушателей курса «{название}» из вашей истории» — по паре с наибольшей долей, только при паре от порога и положительном вкладе, M не меньше 10. У курса другой темы фраза не уходит при сокращении причины до трёх фраз и 180 символов |
| Стартовая подборка | «Стартовый материал по теме «{тема}»» |
| Востребованность | «Один из самых востребованных материалов по теме» — только у тройки самых популярных кандидатов темы |

Следующий шаг берётся из данных материала, при пропуске — по шаблону формата «глагол + объект». При известной длительности шаблон называет время: «Пройдите пункты и отметьте выполненное (около 15 минут)», от 120 минут в часах. У курса длительность относится ко всему курсу, поэтому время шага не называется. Правила микротекстов D19 закреплены тестами: без оценочных слов и долженствования, глагол шага из закрытого списка, экранная типографика. Из данных платного материала выводятся только название, формат, длительность, краткая польза и переход по разрешённой ссылке; без ссылки остаётся действие «Отметить изученным», которое меняет выдачу в том же сеансе. Маршрут на первую неделю строится для статуса `strong` при стадии «идея» или «старт»: до трёх материалов первой страницы, связанных редакционными ссылками.

### 3.7 Оценка на тестовом наборе и офлайн-проверка

Синтетика. Релевантность размечена заранее по шкале 0–3 двумя независимыми разметчиками, которые не видели план и ожидаемые порядки. На восьми профилях с определённой метрикой NDCG@5 персонального подбора 0,92 против 0,72 у подбора по теме; MAP@5 0,80 против 0,42, MRR@5 0,94 против 0,55. Персональный подбор показывает 15 разных материалов из 23 против 12. Это поведение прототипа на вымышленных данных, а не качество на пользователях.

Копия, офлайн-оценка по курсам. 803 пользователя с доступной целью, пять частей по пользователям, популярность и совместные записи считаются по обучающей части. hit@5: популярность 0,69, правила по темам 0,64, совместные записи 0,73; NDCG@5: 0,43, 0,51, 0,60. Правила выигрывают, когда следующий курс той же темы, и проигрывают при смене темы. Польза совместных записей над популярностью сохраняется после поправки на множественность: hit@5 +0,045 [+0,017; +0,072]. EASE отдельно от ленты от совместных записей по первой пятёрке не отличается: +0,001 [−0,012; +0,015]. Внутри ленты он чаще ставит скрытый курс первым и с этапа 4 считает вклад «Выбор слушателей» (13.5). Веса, обученные по журналу, сохраняют знаки ручных, но ставят популярность выше темы; веса продукта по ним не менялись.

Пилот «похожие курсы» проверен на тех же частях. Пары считаются только по обучающей части, порог поддержки 10 задан до прогона. В порядке курсов hit@5 0,67 и NDCG@5 0,54: по NDCG@5 пилот лучше популярности и правил по темам, по hit@5 от популярности не отличается, а правила по темам опережает с малым запасом. Если цель той же темы, hit@5 0,98; если другой — 0,40 против 0,34 у правил и 0,59 у совместных записей. Простые совместные записи точнее пилота и после поправки на множественность. Разбор после прогона относит разницу к тогдашнему вкладу темы истории +1,0. Пороги поддержки 5 и 20 меняют метрики не больше чем на 0,01. На экране, где статьи тем истории делят пятёрку с курсами, курс-цель другой темы виден только у 0,08 пользователей.

Вложенный выбор веса темы истории выполнен по заранее записанному правилу. Сетка — 0,1, 0,25, 0,5 и 1,0, вес выбирается по NDCG@5 на внутренних частях обучающей части. Во всех пяти внешних частях выбран 0,1. На проверочных частях он лучше веса 1,0: hit@5 0,72 против 0,67, NDCG@5 0,58 против 0,54. При цели другой темы hit@5 растёт с 0,40 до 0,54, при цели той же темы падает с 0,98 до 0,94; на экране курс-цель другой темы виден у 0,41 пользователей вместо 0,08. Оговорки: 0,1 — нижняя граница сетки, а повод для выбора и направление сетки подсказал разбор на тех же проверочных частях. Поэтому сравнение не служит независимым подтверждением, его дадут новые данные или онлайн-сравнение. На этапе 3 пользователь принял вес 0,1, он применён в продукте. Перед правкой сетка с нулём (R33) показала, что рядом с парами вес 0 и 0,1 на всех пользователях неразличимы: hit@5 +0,014 [0,000; +0,027].

Этап 3. Каскад «правила отбирают кандидатов, похожие курсы ранжируют внутри» (R06) проверен офлайн и в продукт не вошёл. Вложенный выбор размера отбора во всех частях взял «все», и каскад совпал с простыми совместными записями. Против продукта с весом 1,0 hit@5 +0,062, но при цели той же темы −0,074, за границей −0,05, заданной до прогона. Против веса 0,1 NDCG@5 +0,014, hit@5 без значимой разницы. Слияние рангов, попарная регрессия и усадка пар (R34, R36, R31) простые совместные записи не обгоняют. Точность правил по темам заметно держится на популярности: при случайном порядке равных hit@5 падает с 0,64 до 0,48 (R35).

Эталон на синтетике расширен 26 профилями E01–E26 той же слепой процедурой (R29): два разметчика с разными установками совпали в 95,5 % пар, κ Коэна 0,854. Из 78 расхождений с подбором по теме 38 разметка оценивает выше у персонального подбора, 22 — ниже (R32). Сильнее всего помогает признак текста задачи, срез с регрессией — уровень. `catalog` знает про источники и нормализацию, но не про веса. `ranking` работает с каноническими материалами и профилем и не знает про HTTP. `api` переводит запросы и ответы, `GET /metrics` подключается в `main.py`. Фронтенд не ранжирует и не интерпретирует поля сверх контракта.

### 4.4 Контракт API

`POST /api/recommend`: `task` до `MAX_TASK_LENGTH` символов, по умолчанию 300, пустая строка допустима; `stage` — `idea`, `start`, `growth`; `experience` — `none`, `some`, `experienced`; `format_pref` — `quick`, `template`, `course`; `industry` — код сферы; `topic` — явный выбор из уточнения; `history` до 200 событий; `profile_id` подставляет синтетическую историю только в демо-режиме; `limit` от 1 до 10; `method` — `personal` или `baseline`. `limit` и `seq` события истории принимают только целые числа JSON: строка `"5"` и `true` получают 422, `8.0` принимается как 8. Схема задаёт для `task` жёсткий предел 2000 символов, рабочий предел сервис сообщает в `GET /api/meta` и проверяет при подборе.

Ответ: `request_id`, равный заголовку `X-Request-Id`, `status`, `detected_topics`, `message`, `clarification`, `items` с полями карточки, причинами, пометками, оценкой и вкладами признаков, `route`, `total_candidates`. `POST /api/compare` возвращает оба метода и `diff`. `GET /api/ready` сообщает готовность каталога, его опрашивает `HEALTHCHECK` образа; `GET /api/live` отвечает, пока жив процесс. `GET /metrics` отдаёт метрики Prometheus только при `METRICS_ENABLED=true`, в схему не входит, без флага отвечает 404.

Ошибки — единый объект `error` с кодом, сообщением и не более 10 подробностей: 422, 413, 404, 405, 503, 500. Ошибки 404, 413, 422 и 503 описаны в `/openapi.json` моделью `ErrorResponse`, поля `code`, `message` и `details` обязательны, `details` может быть пустым. Источник истины — `backend/app/schemas.py` и `/docs`. Контракт закреплён снимком `backend/tests/openapi.snapshot.json`, типы интерфейса генерируются из копии схемы.

### 4.5 Запуск и окружение

Команда проверяющего: `docker compose up --build`, интерфейс на `http://localhost:8000`. Других способов сборки нет. Переменные окружения и подключение своей выгрузки описаны в [README](../README.md). Для пилота добавлены `CATALOG_PAIRS_PATH` и `PAIRS_MIN_SUPPORT`. Первая задаёт файл пар. Без неё синтетический каталог берёт пары из комплекта, а источники `sqlite` и `file` работают без «похожих курсов». Вторая задаёт порог поддержки, по умолчанию 10. `METRICS_ENABLED` включает `GET /metrics`, по умолчанию `false`. Недопустимое значение `CATALOG_SOURCE`, `DEMO_MODE`, `METRICS_ENABLED`, `LOG_LEVEL`, `MAX_TASK_LENGTH` или `PAIRS_MIN_SUPPORT` останавливает запуск до старта сервера одной строкой «Запуск остановлен: …».

Dockerfile многостадийный: сборка интерфейса на Node, рабочий образ Python 3.12 с зависимостями из блокировки с хешами, синтетическими данными и `dist/`. Контейнер работает без привилегий, с ограничениями ресурсов, exec-формой команды `python -m app.serve` и проверкой готовности по `/api/ready`. Workflow `.github/workflows/docker-check.yml` состоит из пяти заданий: тесты бэкенда на Python 3.12 с ruff, mypy и порогами покрытия ветвей, тесты интерфейса со сверкой схемы API и ESLint, линт Dockerfile и контекста сборки, аудит зависимостей. Образ собирается один раз: то же задание сканирует его trivy, пишет SBOM, проверяет контейнер, интерфейс в Chromium и Lighthouse CI. По понедельникам workflow идёт по расписанию всеми заданиями, необязательный нагрузочный шаг — только по расписанию и вручную. `mutation.yml` раз в неделю запускает мутационное тестирование mutmut по `ranking/`. Образ собирался и проверялся на локальном стенде с Docker на предыдущей версии кода, до ленты по профилю (7.1, E1). На текущем коде сборка в Docker не повторялась, workflow не запускался ни разу: первый прогон CI во внешнем репозитории станет их проверкой. Интерфейс компилирует TypeScript 6.0, тот же пакет использует ESLint: typescript-eslint пока не поддерживает TypeScript 7.

### 4.6 Безопасность по умолчанию

- Вход проверяется до ранжирования: тело до 64 КБ, длина задачи, размер истории, перечисления, формат кодов материалов.
- Заголовки безопасности и CSP без `unsafe-inline` на всех ответах приложения; сервис в Docker публикуется только на 127.0.0.1; CORS не включён.
- Кеширование: статика `immutable`, HTML `no-cache`, справочники с `ETag`, ответы подбора `no-store`; ответы от 1 КБ сжимаются.
- Каждый ответ несёт `X-Request-Id`, подбор — `Server-Timing`. Журнал пишет код запроса, метод, путь, статус, число кандидатов и длительность, но не текст задачи.
- `GET /metrics` в формате Prometheus есть только при `METRICS_ENABLED=true`; по умолчанию адрес отвечает JSON 404, как неизвестный путь. Метки — шаблон маршрута, метод и код ответа, без пути и данных запроса. Аутентификации у адреса нет, как и у API.
- Текст из API выводится как текст. Ссылки только `http` и `https` из каталога. В ответе нет текстов материалов, идентификаторов реальных пользователей и ключей.

## 5. Спецификация интерфейса

### 5.1 Макет и кит

Интерфейс собирается только из компонентов [UI-кита](ui-kit.md): токены, базовые компоненты на нативных элементах HTML, компоненты экрана. Витрина всех компонентов — страница `/kit.html`.

### 5.2 Сценарий экрана

1. Пользователь вводит задачу своими словами; уточнения стадии, опыта, формата и сферы свёрнуты и помечены как необязательные.
2. Нажимает «Подобрать материалы»: форма блокируется, сразу появляется строка состояния. Прежнее содержимое остаётся на месте, приглушённое и неактивное; если ответ дольше 400 мс, его сменяют скелетоны (D10).
3. Получает выдачу: пять карточек, маршрут, «Показать ещё». Строка состояния после ответа визуально скрыта и только озвучивает число материалов и допущения (раздел 11).
4. Читает причину и следующий шаг, открывает материал, если ссылка разрешена, или отмечает его изученным — история сеанса меняет выдачу.
5. При слабом совпадении выбирает тему в баннере, при пустой выдаче — тему или стартовую подборку, при ошибке — «Повторить». Введённые данные сохраняются.

### 5.3 Состояния

| Состояние | Что видит пользователь | Данные | Доступность |
| --- | --- | --- | --- |
| Начальный | Заголовок, поле задачи, переход «Выбрать готовую задачу», уточнения, кнопка, три примера | — | Подписи видимы, чипы — радиогруппы, список — `select` |
| Загрузка | Повторная отправка блокируется сразу, появляется строка состояния. Через 400 мс поля блокируются и подпись кнопки меняется на «Подбираем…». Первые 400 мс прежнее содержимое приглушено и неактивно, затем три скелетона | запрос отправлен | Строка состояния `role="status"` |
| Выдача | Карточки, маршрут, «Показать ещё» | `strong` | Порядок карточек совпадает с порядком чтения, фокус на первой карточке; скрытая строка состояния озвучивает итог |
| Слабое совпадение | Баннер уточнения с чипами тем на нейтральном фоне, затем смешанная выдача или подбор по истории | `weak`, `clarification` | Баннер `role="status"`; фокус на первой карточке, окно показывает и вопрос баннера |

### 5.4 Карточка материала

Позиция, название, бейджи формата, длительности, доступа и уровня, пометка истории, краткая польза платного материала, блоки «Почему подходит» и «Следующий шаг», действия. Под причиной стоят пометки «Совпало» (D09): до четырёх признаков с положительным вкладом, на которые повлиял пользователь задачей, уточнениями или историей, без чисел. «Уровень» ставится только при точном совпадении уровня материала с опытом. У подбора по теме пометок нет. Переход «Открыть материал», «Открыть страницу курса» или «Открыть страницу материала» показывается только при разрешённой ссылке; без ссылки карточка сообщает «Ссылка на платформу не передана». Полное содержание платного материала не выводится.

### 5.5 Адаптивность и доступность

Одна колонка до 800 px, две колонки шире. Цель — WCAG 2.2 AA: высота интерактивных элементов не меньше 44 px, цель указателя не меньше 24×24 px, от 320 px без горизонтальной прокрутки, видимый фокус, все действия с клавиатуры. Цвет не единственный носитель смысла: платность, пометки истории, выбранный чип и ошибка дублируются текстом или начертанием. При красном акценте роли разведены не цветом (D03): баннер уточнения стоит на нейтральной поверхности, баннер ошибки несёт видимую подпись «Ошибка», вторичные ссылки идут в цвете текста с подчёркиванием. Контраст пар токенов и различимость состояний при симуляции дальтонизма проверяются скриптами, см. [UI-кит](ui-kit.md). Фокус после ответа стоит на видимом элементе: первой карточке, заголовке пустой выдачи или сравнения, кнопке «Повторить». В режиме высокой контрастности Windows выбранный чип и вкладка залиты системным цветом выделения. Строки выводятся с неразрывными пробелами, текстовый блок не шире 65ch (D09).

### 5.6 Демо-режим и сравнение

Панель «Демо-режим» показывает выбор тестового профиля и переключатель «Сравнить с подбором по теме»; появляется только при `DEMO_MODE`. Сравнение подаёт один профиль и один каталог в оба метода. Если у метода нет выдачи, колонка показывает его сообщение и стартовую подборку; число изменившихся позиций называется только при выдаче у обоих методов. При пустой задаче и истории профиля, как у P11, строка состояния называет оба метода: «Сравнение готово. Без задачи подбор по теме показывает стартовую подборку, персональный — подбор по истории.» Сравнение печатается двумя колонками рядом.

### 5.7 Тексты интерфейса

Ключевые строки: «Найдите материалы для бизнеса», «Что вы хотите сделать?», «Уточнения — необязательно», «Подобрать материалы», «Подбираем…», «Почему подходит», «Совпало», «Следующий шаг», «Открыть материал», «Открыть страницу курса», «Открыть страницу материала», «Отметить изученным», «Ссылка на платформу не передана», «Уточните тему», «По запросу материалов пока нет», «Стартовая подборка», «Не удалось получить подборку», «Повторить», «Это предел. Поле вмещает 300 символов.» Строки интерфейса проходят экранную типографику и правила микротекстов D19, их проверяют тесты интерфейса.

## 6. Порядок реализации

Этап 1 — первый сквозной сценарий: каркас бэкенда, подбор по теме и тесты, персональный подбор со статусами, причинами и маршрутом, API, фронтенд, Docker, источник SQLite с отчётом покрытия, протокол прогона. Этап 2 — проверки безопасности и нагрузки, офлайн-оценка по курсам, расширенный набор метрик, пилот «похожие курсы» с подбором по истории при пустой задаче, фраза D01, меры доступности при красном акценте, схема событий для эксперимента, комплект с этим планом и UI-китом. Параллельно шла первая волна улучшений по литературе, которая не меняет размеченную выдачу P01–P10. Её итоги и дальнейшие кандидаты описаны в разделе 11.

### 7.3 План измерения эффекта

Гипотеза: персональная выдача повышает долю пользователей, которые начинают материалы, и в итоге покупки и активные дни. Единица рандомизации — пользователь, группа закрепляется при повторных визитах. Контроль — текущий путь выбора материалов, тест — экран рекомендаций.

- Критерий общей оценки, когда обе группы видят список, например персональный подбор против подбора по теме: старт рекомендованного материала в течение 7 дней после первого показа списка. Рекомендованным считается материал из списка своей группы. Старт любого материала за 7 дней в таком сравнении служит охранной метрикой: рост стартов рекомендованного не должен идти за счёт остальных.
- В сравнении экрана рекомендаций с текущим путём без списка старт рекомендованного не определён, сопоставим только старт любого материала за 7 дней. Станет ли он критерием этого сравнения или основное сравнение пойдёт между двумя списками, решает пользователь (раздел 11).
- Цели кейса: конверсия в подтверждённую покупку за 30 дней и среднее число активных дней за 28 дней, включая нули.
- Охранные метрики: доля статусов `cold` и `empty`, задержка p95, доля платных в выдаче, проверка равенства долей групп до чтения результатов, потеря событий.
- Процедура: A/A перед первым A/B, не меньше двух полных недель с отчётом по неделям, остановка по заранее заданному объёму, снижение дисперсии CUPED по визитам за 28 дней до эксперимента. При малом трафике первым идёт интерливинг «персональный против подбора по теме».
- События: назначение группы, показ экрана, показ выдачи с кодом запроса, позициями и типами причин, клик по карточке, старт и завершение материала, визит, покупка. Идентификаторы псевдонимные, текста задачи в событиях нет.

Объём выборки для сравнения двух долей при уровне значимости 0,05 и мощности 0,8, пользователей на группу:

| Базовая конверсия | Прирост 10 % | Прирост 20 % | Прирост 50 % |
| ---: | ---: | ---: | ---: |
| 1 % | 163 095 | 42 693 | 7 750 |
| 3 % | 53 211 | 13 914 | 2 518 |
| 5 % | 31 234 | 8 158 | 1 471 |

Доля платных среди записей на курсы в копии — 0,2 %, поэтому покупка как единственный критерий потребовала бы сотен тысяч пользователей. Если разделить пополам 7 342 пользователя журнала, по 3 671 на группу, старт за 7 дней с базовой долей 0,05 обнаружим от прироста 30 %, покупка с базовой долей 0,2 % — только от 196 %. Базовая доля старта — допущение: в копии её нет. Какие события платформа пишет и какое окно допустимо, уточняется у владельца платформы; до этого эффект остаётся гипотезой.

## 8. Критерии готовности

1. Из чистой копии проект запускается по README локально и через Docker; интерфейс и `/api/health` доступны.
2. P01 и P02 дают ожидаемые тройки; подбор по теме одинаков для обоих, персональный различается, сравнение это показывает.
3. Пустая форма, неоднозначная задача и тема вне каталога дают стартовую подборку, уточнение и сообщение о пробеле.
4. Отключение API приводит к баннеру ошибки и повтору без потери ввода.
5. Карточка платного материала показывает только разрешённые поля; без ссылки кнопки перехода нет.
6. «Отметить изученным» меняет выдачу в том же сеансе.
7. pytest проходит, включая тесты верности причин, лимитов и загрузчика на фикстурах.
8. В комплекте нет закрытых данных, ключей и локальных путей автора.
9. Сценарий проходится на 390 px с клавиатуры.

## 10. Ограничения

- Демонстрация идёт на синтетическом каталоге; прогон на копии выгрузки выполняется только у автора.
- Влияние на покупки и активные дни не измерено; нужен онлайн-эксперимент с телеметрией по 7.3.
- Уровень размечен только у курсов, история есть только по курсам; свежесть материалов не вычисляется.
- Аутентификации нет: прототип рассчитан на локальный запуск.
- Названия в копии нейтральные, поэтому поиск по названию может пропустить подходящий материал.
- Docker-сборка, контейнерные шаги, Lighthouse, trivy и SBOM проверены 13 ноября 2026 года на локальном стенде с Docker, на версии кода до ленты по профилю. На текущем коде они не повторялись. Первого прогона workflow во внешнем репозитории и полного прогона мутационного тестирования пока не было.
- Нагрузка измерена на локальной машине, цифры служат ориентиром. В Docker с одним ядром копия держит пороги на 20 запросах в секунду, на 50 и 100 выходит за пороги задержки. Lighthouse в Docker прошёл все бюджеты, медиана TBT 8,7 мс.
- Проход с экранным диктором и проверку в настоящем режиме высокой контрастности Windows выполняет человек: эмуляция в браузере их не заменяет. Сессий пользовательской проверки и эвристического ревью двумя людьми не было.
- Пилот «похожие курсы» проверен офлайн только на курсах. У статей журнала нет: их проверяют только размеченные профили и псевдоэталон по редакционным связям.
- Главная потеря качества — разбор задачи словарём: у 7 из 26 новых размеченных профилей тема не распознана. Правки словаря меняют распознавание и ждут решения пользователя.
- Эталон на синтетике — 36 профилей и 23 материала, разметка сделана моделью в двух независимых установках.

## 11. Развитие

Кандидаты улучшений взяты из обзора литературы по рекомендациям, веб-инженерии и дизайну и разбиты на две волны. Первая волна не требует решений пользователя и не меняет размеченную выдачу P01–P10. Пункты второй волны меняют выдачу, контракт API или макет либо требуют телеметрии, поэтому каждый ждёт решения пользователя или данных платформы.

Сделано в первой волне:

- Метрики и офлайн-оценка: модуль метрик с точностью, полнотой, MRR, MAP, покрытием, разнообразием, Джини и экспозицией (R05); парный бутстреп с поправкой Холма (R01); нормированные совместные записи (R03) и EASE (R04); проверка весов обученной моделью (R08); свойства маршрута (R13, частично); верность объяснений (R21).
- Сервис: заголовки безопасности и CSP без `unsafe-inline` (W01), кеширование и сжатие (W03), пределы uvicorn и контейнера (W07), коды запроса и `Server-Timing` (W11), готовность и живость (W13), схема журнала (W16), таблица ASVS (W17), свойства Hypothesis, Schemathesis и снимок схемы API (W10), метрики за флагом (W12).
- CI: строгие ruff, mypy и ESLint с порогами покрытия ветвей (W09), Lighthouse CI (W04, частично), цепочка поставки с блокировками по хешам, аудитом и SBOM (W06), мутационное тестирование (W21), линт Dockerfile и контекста сборки (W20, частично); первого прогона пока нет.
- Нагрузка: постоянный поток запросов (W08, частично) и критерии SLO (W15), без Docker-стенда (7.2).
- Интерфейс: пометки «Совпало», типограф и предел строки 65ch (D09, R19); задержка скелетонов (D10); правила микротекстов (D19); симуляция дальтонизма (D18); пробелы WCAG 2.2 (W05); шрифт без сдвига макета, переносы, склонения и печать сравнения двумя колонками (W14); ручной чек-лист доступности с автоматической проверкой принудительных цветов и увеличения 400 % (W19, частично: проход с экранным диктором выполняет человек, раздел 10). По эвристическому ревью исправлены сообщение у предела поля задачи (ИИ-5) и фокус после ответа (ИИ-10).
- Документы измерения: схема событий, иерархия метрик и карточка эксперимента 7.3 (R16, R23 частично, R25), карта «элемент объяснения → цель → метрика» (R17), гипотезы изменений ранжирования (R22), протокол пользовательской проверки (D07, D15), эвристическое ревью (D13, частично), таблица HEART (D20), таблица вопросов анкеты в README (D12). Прогонов с участниками не было.

Вторая волна. По решению пользователя сделаны пилот «похожие курсы» вместе с переносом веса недоступного курса (R15) и фразой «N из M» (R18), фраза D01 и меры D03 при красном акценте. Как избыточные для демо отклонены глубокие последовательные модели, бандит над всем каталогом, полный стек OpenTelemetry, тёмная тема и APCA как критерий контраста.

- расширять ли словарь по пробелам, найденным R29 и R30: «раскручивать», «покупатели», «открываю ИП», «ЕГРИП», «таск-трекер» и другие;
- убирать ли вклад темы из оценки: выключение не меняет ни одной пятёрки, но убирает фразу о теме (R27);

- критерий сравнения экрана рекомендаций с текущим путём и отсчёт окна раннего показателя от первого показа (7.3);
- стиль контурной кнопки платного материала: в тоне акцента, как сейчас, или в цвете текста;
- показывать ли строку состояния после ответа: сейчас после ответа она визуально скрыта и только озвучивает итог;

## 13. Лента по профилю

Раздел пронумерован как раздел 13 рабочего плана: на него ссылаются комментарии кода ленты. Раздела 12 в краткой версии нет, итоги этапа 3 пересказаны в 3.7 и разделе 11.

### 13.1 Требование

Заказчик посмотрел прототип и попросил рекомендацию по профилю, а не поиск по задаче. Нужны лента до 50 карточек для клиента с историей, видимая оценка с разбором по источникам, возможность увидеть, что меняется при другом профиле, модель на математике без языковой модели и метрика на журнале. Подбор по задаче остаётся дополнительным путём.

### 13.2 Сценарий экрана

Вход устроен как развилка из трёх путей: «Клиент с историей», «Новый клиент» и «Подбор по задаче». Первым открыт клиент с историей, вводить ничего не нужно. Клиент выбирается из списка или по коду. Лента показывает карточки по убыванию оценки, первые 20 и по кнопке первые 50. На карточке четыре элемента: название, строка сведений, одна причина и полоса оценки по источникам. По кнопке «Как посчитано» открываются вклады со свидетельствами и таблица, где карточка стоит рядом с первой. Над лентой стоит таблица первой и последней карточек. Отметки истории и кнопка «Отметить пройденным и пересчитать ленту» меняют историю, экран называет новые, ушедшие и сменившие место карточки. После смены клиента экран называет число общих карточек двух лент. Список «Сравнить с клиентом» ставит двух клиентов рядом: число общих карточек в первых 10 и в первых 20, полосы долей источников у каждого и первые десять карточек обеих лент по местам. Флажок «Вид клиента» оставляет от экрана то, что увидел бы сам клиент: карточки с названием, сведениями и одной причиной, без оценок, расчёта и панелей. На узком экране панели истории и состава оценки стоят после ленты.

### 13.3 Данные

- Обезличенная копия: 7 342 пользователя с записями на курсы, 79 % записаны ровно на один курс. Журнал есть только по курсам, статей и сведений о пользователе в нём нет.
- Каталог ленты в комплекте: 166 вымышленных материалов по 13 темам. Размеченный каталог из 23 материалов входит в него без изменений, поэтому подбор по задаче и его метрики от ленты не зависят.
- Клиенты в комплекте: 24 вымышленных клиента трёх сегментов из вымышленного журнала на 6 000 клиентов. По тому же журналу посчитаны пары совместных записей новых курсов. Журнал повторяет агрегаты копии, а не её записи, и в комплект не входит.
- С подключённой базой клиенты читаются из её журнала записей, если в нём есть коды пользователей. Профили из `DEMO_PROFILES_PATH`, у которых есть история, стоят в списке первыми.

### 13.4 Модель

Оценка карточки равна сумме вкладов, округлённых до сотых, порядок идёт строго по оценке.

| Вклад | Формула | Когда начисляется |
| --- | --- | --- |
| Выбор слушателей | 12 × сумма весов модели EASE по курсам истории. Веса считаются по счётчикам журнала записей и приведены к единицам доли слушателей; верхней границы нет, отрицательная сумма остаётся вычетом. Свидетельством служит запись с наибольшим весом: N из M слушателей курса истории | Кандидат является курсом, а в истории клиента есть курс с журналом записей: не меньше 10 слушателей |
| Похожее содержание | 1,7 × косинус между профилем интересов и материалом; признаки: темы, признаки текста, стадии, уровень, сферы, вес признака растёт с его редкостью в каталоге | Материалы других форматов; курсы у клиента без курсов в истории; все материалы каталога без пар |
| Совет редакции | 0,5, если материал стоит в блоке «далее» у материала истории | Там же, где похожее содержание |
| Популярность | 1,0 × нормированная популярность | Всегда |
| Доступ и цена | ±0,2 у платного материала: надбавка клиенту с оплатами, вычет клиенту без оплат | Всегда, вес можно обнулить в запросе |
| Анкета и задача | Вклады раздела 3.2 | Если поле анкеты или задача заданы |
| Начатое, уже открывали | +2,0 и −1,5 | Материал из истории |

Пройденный и купленный материал в ленту не входит. Причина на карточке называет источник о самом клиенте с наибольшим вкладом; популярность и доступ называются, только если таких вкладов нет.

### 13.5 Оценка

Порядок курсов проверен на журнале записей по протоколу O1 (3.7): у пользователя с двумя и более курсами одна запись скрыта, остальные служат историей. Веса выбирались на трёх частях из пяти по NDCG@5, подтверждение шло на двух оставшихся: 320 пользователей.

| Метод | Скрытый курс первым | В первых пяти | NDCG@5 |
| --- | ---: | ---: | ---: |
| Популярность | 0,17 | 0,69 | 0,43 |
| Только совместные записи | 0,39 | 0,73 | 0,58 |
| Лента с долей слушателей, прежняя формула | 0,38 | 0,73 | 0,57 |
| Лента | 0,43 | 0,74 | 0,60 |

Лента против совместных записей: скрытый курс первым чаще на 0,041 с 95 % интервалом от +0,013 до +0,069, NDCG@5 выше на 0,017 с интервалом от −0,002 до +0,034. Против популярности NDCG@5 выше на 0,168 с интервалом от +0,129 до +0,207. Модель EASE против доли слушателей в той же ленте: скрытый курс первым чаще на 0,053 с интервалом от +0,019 до +0,087. У 241 пользователя со строгим порядком событий скрыт последний курс: лента ставит его первым у 83 %, популярность у 1 %. У 562 пользователей скрыта случайная запись: 29 % и 24 %.

Что пробовали и что получили на частях выбора:

| Вариант | Результат | Решение |
| --- | --- | --- |
| Модель EASE вместо доли слушателей | На всех 803 пользователях скрытый курс первым у 0,45 против 0,42, разница +0,030 с интервалом от +0,011 до +0,050; обе группы пользователей выше. Отдельно от ленты EASE отличался от совместных записей на 0,001 в первой пятёрке | Включено: перевес виден в первом месте |
| Сходство содержания у курсов вместе с выбором слушателей | NDCG@5 ниже на 0,020 при весе 0,5 и на 0,033 при весе 2 | Не включено: у курсов работает только журнал |
| Совет редакции у курсов | NDCG@5 ниже на 0,003 при весе 0,25 и на 0,009 при весе 1,5 | Не включено |
| Вес глубины события: открыл, начал, прошёл | NDCG@5 ниже на 0,009–0,011 | Не включено |
| Штраф за повтор темы в ленте | На частях подтверждения NDCG@5 курсов 0,589 против 0,595; ленты двух пользователей совпадают на 63 % против 47 %; тем в первой десятке 7,1 против 6,0 | Не включено: порядок строго по оценке |
| Сходство содержания у материалов без журнала | На псевдоэталоне редакционных связей, 1 039 статей и документов: цель в первых 10 карточках у 35 % источников против 16 % при одной популярности, половина подтверждения | Включено, отношение к весу популярности 5 : 3 |

Свойства смешанной ленты на копии: скрытый курс входит в первые 10 карточек у 78 % пользователей; курсы занимают 53 % первой десятки, статьи 47 %; в ленты попадает 31 % доступного каталога; ленты двух случайных пользователей совпадают на 47 %, без сходства содержания на 91 %. Доля курсов получена в прогоне и целью не служит: курсы и статьи идут одной лентой без заданной пропорции (13.9).

Вес популярности общий для всех материалов. Среди одних курсов на частях выбора журнал выбирает для него ноль: NDCG@5 0,617 против 0,593 при весе 1,0. Общий вес 1,0 задаёт положение курсов среди статей; на частях подтверждения лента с ним не ниже ленты с выбранными весами, 0,60 против 0,58. Данными не проверены это взаимное положение, вес совета редакции, доступ, анкета и задача: ни журнал, ни псевдоэталон их не оценивают. Знак и размер вклада доступа и общая лента без доли курсов приняты решением автора (13.9), проверить их можно только на событиях платформы. Связи псевдоэталона выражают мнение редакции, а не поведение читателей. На частях журнала до этого этапа уже проверялось 205 конфигураций, поэтому числа выбора разведочные; опорой служат части подтверждения.

### 13.7 API

- `GET /api/users` отдаёт клиентов для ленты: первые `limit` клиентов, код которых начинается с `q`, без учёта регистра; точное совпадение стоит первым.
- `POST /api/feed` строит ленту: история из `history` или клиента `user_id`, списки `exclude_history` и `add_history`, `limit` до 50, необязательный вес цены. В ответе у карточки оценка, вклады источников со свидетельствами и причина; у вклада, который считает модель, есть пояснение `note`; у ленты история, темы истории, поля анкеты с происхождением и доли источников.
- `GET /api/model-card` отдаёт паспорт модели: числа оценки на журнале, веса и свойства ленты.

Прежние адреса и их контракт не изменились.

### 13.9 Решения

| Решение | Основание | Отвергнуто |
| --- | --- | --- |
| Вход развилкой, первым открыт клиент с историей | Главный сценарий заказчика идёт без ввода текста | Один экран с формой задачи |
| Пройденный материал в ленту не входит | Лента предлагает следующее, пройденное остаётся в истории | Понижать пройденное, как в подборе по задаче |
| Курс оценивается по журналу, остальное по содержанию | Числа 13.5 | Складывать все источники у каждого материала |
| Вклад «Выбор слушателей» считает модель EASE, а не доля N из M | Внутри ленты скрытый курс стоит первым чаще, обе группы пользователей выше (13.5). Объяснение сохранено: свидетельством служит запись журнала с наибольшим весом, в расчёте сказано, что величину вклада считает модель | Оставить долю слушателей ради формулы, которая читается с карточки |
| Один вес популярности для курсов и статей | Иначе популярные курсы без личных свидетельств занимали всю первую десятку | Свой вес популярности у каждого формата |
| Просмотр клиента по коду только в демо-режиме | История по коду без входа в систему служит показу | Отдельная авторизация в прототипе |
| У клиентов комплекта вымышленные истории | Описание данных требует для показа вымышленные профили | Показывать псевдонимные коды копии |
| Каталог ленты отдельный, размеченный входит в него дословно | Метрики подбора по задаче на 23 материалах остаются сравнимыми | Расширить размеченный каталог |
| Вклад доступа: −0,2 платному или подписочному материалу, если у клиента нет оплаченной записи, и +0,2, если есть | Решение автора. Оплат в копии почти нет, поэтому данными знак не проверен | Не снижать оценку платного материала клиенту без оплат |
| Курсы и статьи идут одной лентой без заданной доли | Решение автора. 53 % курсов в первой десятке получены в прогоне на копии и целью не служат | Квота курсов или статей в ленте |
| Курс без записей оценивается по тем же правилам, что остальные курсы | Решение автора: отдельное место на пробу в MVP не нужно, это тема отдельного эксперимента. У клиента с курсами в истории такой курс получает только общие вклады и стоит в конце ленты; метрика скрытой записи его не засчитывает | Отдельное место в ленте для новых курсов; вклад содержания наравне со статьями |
