# План презентации и проверка перед сдачей

| Слайд | Что показать и сверить |
| --- | --- |
| 1. Как проверить | Название прототипа, трек 1, `docker compose up --build`, `http://localhost:8000`, начать с P01 и P02. Поле ссылки на репозиторий оставить пустым до сдачи |
| 2. Задача предпринимателя | Два профиля с близкой задачей. Объяснить, почему им нужны разные форматы и уровень глубины |
| 3. Как работает подбор | Тема, задача, стадия, опыт и история влияют на выбор. Показать холодный старт, объяснение и следующий шаг |
| 4. Демонстрация | Показать P01 и P02 и сравнить с подбором по теме. Дальше показать уточнение P05 или обновление после «Отметить изученным» |
| 5. Результаты | Сверить цифры по [протоколу](../evaluation/track1-first-run.md). Отдельно обозначить синтетические профили и [офлайн-оценку по курсам](../evaluation/track1-offline-courses.md). Статус Docker взять из фактического прогона |
| 6. Как измерить эффект | Объяснить план A/B-эксперимента и метрику подтверждённых покупок после внедрения. Взять детали из раздела 7.3 [плана](PLAN.md#73-измерение-эффекта) |

После экспорта в PDF откройте файл как проверяющий. Убедитесь, что первый слайд даёт воспроизводимый маршрут, снимки читаются, цифры совпадают с протоколом, а карточки используют разрешённые данные.
