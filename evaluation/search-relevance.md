# Офлайн-проверка поиска по словам

Локальный SQLite-каталог содержал 1 086 доступных материалов. На одном каталоге и одной разметке сравнивались персональные рекомендации с отключённым и включённым поиском по словам. Разметка по названиям содержит семь точных, три широких и три запроса без подходящих материалов.

| Группа | Запросов | Hit@3 по правилам | Hit@3 с поиском | NDCG@5 по правилам | NDCG@5 с поиском |
| --- | ---: | ---: | ---: | ---: | ---: |
| Точные | 7 | 3 | 7 | 0,2546 | 0,9894 |
| Широкие | 3 | 1 | 1 | 0,2438 | 0,2438 |
| Все с релевантными материалами | 10 | 4 | 8 | 0,2513 | 0,7657 |

У обоих вариантов 0 ответов со статусом `strong` на трёх запросах без подходящих материалов. Hit@3 считает запросы с оценкой хотя бы 2 в первой тройке. NDCG@5 усредняется по запросам с положительной разметкой. Выборка собрана вокруг проверяемых сценариев и даёт регрессионную оценку для этого каталога.

В разметке `group` принимает значения `exact`, `broad` и `empty`. Поле `task` содержит текст запроса. Поле `grades` сопоставляет идентификаторы материалов с оценками от 1 до 3 и остаётся пустым для `empty`. Разметка реальной выгрузки хранится локально в `data/local/search-relevance.json`.

```powershell
python -X utf8 evaluation/search_relevance.py data/local/alfa-course-details/catalog.sqlite3 data/local/search-relevance.json --signals data/local/alfa-course-details/catalog-signals.sqlite3
```

## Подбор по действию и объекту

На повторном импорте из бэкапа получено 1 086 доступных материалов и 638 кратких описаний открытых индексируемых статей. Точка отсчёта — ранжирование из `6582edd`. Действующий алгоритм сравнивался с поиском задачи по названиям, с добавлением описаний и сведений о курсах, затем с добавлением лучших абзацев открытых статей.

Набор из 120 запросов разделён на 60 для разработки и 60 для контроля, по 15 точных, широких, переформулированных и без ответа в каждой части. Семейства задач не пересекаются. Для разметки использовалось объединение первых 20 карточек каждого варианта и результатов отдельного поиска по каталогу. Разметка выполнена по названиям одним оценщиком. В пуле были скрыты метод и позиция карточки. Оценки для одного семейства переиспользовались между его формулировками. Набор показывает поведение на сценариях локального каталога.

### Контрольная часть

| Группа | Текущий, Hit@3 / NDCG@5 | Названия | Метаданные карточек | С абзацами |
| --- | ---: | ---: | ---: | ---: |
| Точные, 15 | 9 / 0,4196 | 9 / 0,4196 | 9 / 0,4196 | 9 / 0,4196 |
| Широкие, 15 | 1 / 0,0543 | 1 / 0,0543 | 1 / 0,0647 | 1 / 0,0647 |
| Переформулировки, 15 | 1 / 0,0314 | 1 / 0,0314 | 1 / 0,0314 | 1 / 0,0314 |
| Широкие и переформулировки, 30 | 2 / 0,0428 | 2 / 0,0428 | 2 / 0,0480 | 2 / 0,0480 |

Для широких задач и переформулировок до ранжирования дошло 46,0% размеченных релевантных карточек. Среди самих кандидатов 0,83% имели оценку 2 или 3. Отбор кандидатов общий для всех четырёх вариантов. Число новых ложных `strong` равно нулю. Пять существующих случаев приходятся на запросы, где алгоритм нашёл общую тему без подходящей карточки.

На части разработки NDCG@5 для широких задач и переформулировок составил 0,0571, 0,1900, 0,2124 и 0,2393 соответственно. На контроле прирост лучшего варианта по карточкам составил 0,0052 при пороге 0,05. Абзацы дали 0,0000 дополнительного прироста при пороге 0,02. Для сервиса по умолчанию сохранён `legacy`. Вариант с метаданными доступен для локальной проверки через `CATALOG_RELEVANCE=task`.

Замер p95 для `POST /api/recommend` в одном прогретом приложении на Python 3.12 дал 13,57 мс для текущего алгоритма, 13,30 мс для названий и 15,28 мс для метаданных. Использовались 60 контрольных запросов и пять повторов после прогрева.

### Повторный прогон

Файл запросов содержит `task`, `group`, `split` (`dev` или `test`), `family` и необязательный массив `manual` с найденными вручную карточками. Команда `--pool` создаёт новый локальный файл с карточками в порядке, независимом от метода. Заполните `grades` оценками 0–3. Размеченные файлы и исходные данные храните в `data/local`.

```powershell
$catalog = 'data/local/alfa-course-task'
$backup = 'C:/путь/alfa_course_hackathon.backup'
python -X utf8 evaluation/search_relevance.py "$catalog/catalog.sqlite3" data/local/task-queries.json --signals "$catalog/catalog-signals.sqlite3" --backup $backup --pool data/local/task-review.json
python -X utf8 evaluation/search_relevance.py "$catalog/catalog.sqlite3" data/local/task-labels-final.json --signals "$catalog/catalog-signals.sqlite3" --backup $backup --split test
python -X utf8 evaluation/search_relevance.py "$catalog/catalog.sqlite3" data/local/task-labels-final.json --signals "$catalog/catalog-signals.sqlite3" --split test --benchmark 5
```

`--backup` добавляет эксперимент с абзацами в изолированном Docker. `--benchmark` использует зависимости из `backend/requirements-dev.txt`. Браузерная проверка локального режима запускается командой `npm --prefix evaluation/e2e run check:task-search` при работающем приложении с `CATALOG_RELEVANCE=task` и включённым режимом сравнения.

## Глобальный и гибридный поиск

Индекс FTS5 и векторы E5 построены для 1 086 доступных карточек. Пороговые значения проверены на прежней части разработки. Следующая таблица относится к 30 широким запросам и переформулировкам из прежней контрольной части. У пяти методов 323 попадания в первую десятку без оценки в старом пуле. Метрики служат диагностикой.

| Метод | NDCG@5 | Hit@3 | Recall@30 по прежней разметке | Ложные `strong` на 15 запросах |
| --- | ---: | ---: | ---: | ---: |
| `legacy` | 0,0428 | 2 из 30 | 19,39% | 5 |
| `task` | 0,0480 | 2 из 30 | 20,50% | 5 |
| Глобальный BM25 | 0,0406 | 4 из 30 | 4,17% | 0 |
| E5 | 0,1753 | 9 из 30 | 17,50% | 0 |
| Гибрид | 0,1557 | 9 из 30 | 20,28% | 0 |

Прирост Recall@30 гибрида составил 0,89 п. п. при пороге выпуска 15 п. п. Дополнительные открытые описания на прежней части разработки подняли NDCG@5 BM25 с 0,0741 до 0,1189 и Hit@3 с 4 до 6 из 30. В этом прогоне также есть карточки без оценок. Корпус для выпуска выбирается по новой разметке. Текущий режим по умолчанию — `legacy`.

В прогретом контейнере с 2 vCPU и лимитом памяти 1,5 ГиБ p95 HTTP на 160 запросах составил 33,42 мс, пиковый RSS процесса — 1 236 МиБ. Chromium и axe-core прошли локальные проверки гибридного режима на 390 и 1120 px.

### Слепая разметка и калибровка

Подготовлены 160 новых запросов. В каждой из двух частей 20 точных, широких, переформулированных и запросов без ответа. Файлы запросов и отдельные пакеты для двух оценщиков находятся в `data/local`. Оценщик присваивает карточкам от 0 до 3 по названию и разрешённым полям. Найденные вручную материалы можно добавить в массив `manual` перед сборкой основного пакета. Храните исходные независимые оценки отдельно. После разбора расхождений используйте согласованные оценки в обоих файлах контрольного прогона.

```powershell
$r = 'data/local/alfa-course-task'
$argsSearch = @("$r/catalog.sqlite3", '--signals', "$r/catalog-signals.sqlite3", '--index', "$r/search", '--model', 'data/local/e5-small')
python -X utf8 evaluation/hybrid_search.py @argsSearch data/local/hybrid-queries.json --split dev --pool data/local/review-dev.json --second-pool data/local/second-dev.json
python -X utf8 evaluation/hybrid_search.py @argsSearch data/local/graded-dev.json --split dev --calibrate data/local/policy.json
python -X utf8 evaluation/hybrid_search.py @argsSearch data/local/hybrid-queries.json --split test --policy data/local/policy.json --pool data/local/review-test.json --second-pool data/local/second-test.json
python -X utf8 evaluation/hybrid_search.py @argsSearch data/local/graded-test.json --split test --policy data/local/policy.json --second-review data/local/adjudicated-second-test.json
```

Для сравнения дополнительных описаний используйте `--extra-backup` с `--split dev --diagnostic`. Для локальной проверки интерфейса запустите `node evaluation/e2e/check_global_search.mjs` против работающего режима `lexical` или `hybrid`. Результат `quality_winner` относится к офлайн-метрикам. Перед включением дополнительно сверяются задержка и память.
