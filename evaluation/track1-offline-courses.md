## Протокол

- **Пользователи.** Записи `CourseUserBindings` без удалённых: 10 050 строк, 7 342 пользователя. С двумя и более курсами — 1 562, из них со строгим порядком событий (все `EventOrder` различны) — 300. Повторов пары «пользователь — курс» нет.
- **Цель и вход.** У пользователей со строгим порядком цель — последний курс по `EventOrder`, вход — остальные записи. У остальных цель — один случайный курс с фиксированным зерном. События входа переводятся в историю запроса по PLAN.md, 2.4: статус 0 → `view`, 1 → `start`, 2 → `complete`, `IsPaid` → `purchase`; `seq` = `EventOrder`.
- **Кандидаты.** Доступные курсы каталога — 26 из 37 — без курсов входа, в среднем 25. Пользователь, чья цель недоступна, в метрики не входит: таких 759 из 1 562. Оценено 803 пользователя: 241 со строгим порядком и 562 со случайной целью.
- **Обучающая и проверочная части.** Пользователи с двумя и более курсами разбиты на пять частей; каждая часть по очереди проверочная, остальные четыре вместе с 5 780 пользователями одного курса — обучающая. Популярность и пары совместных записей считаются только по обучающей части, поэтому цель пользователя в его собственные счётчики не попадает.
- **Методы.** Популярность — число записей на курс. Правила по темам — персональный подбор приложения без текста задачи: кандидаты тем курсов входа, вклад темы, продолжение по `recommended_next` и история; остаток пятёрки заполняется по популярности. Совместные записи — сумма по курсам входа доли их пользователей, записавшихся и на кандидата; равенства решает популярность.
- **Метрики.** hit@3, hit@5 и NDCG@5 с бинарной релевантностью, как в плане, плюс hit@1 и распределение позиции цели, потому что разница методов проявляется на первой позиции. Для hit@3 и hit@5 указана половина 95 % доверительного интервала по нормальному приближению. Для сравнения приведено ожидание случайного порядка.

Отличия от PLAN.md, 3.7: пять частей вместо одного разбиения 80 на 20, чтобы оценить всех 1 562 пользователей, а не пятую часть; популярность, как и совместные записи, считается по обучающей части; пользователи с недоступной целью исключены, потому что продукт недоступные курсы не показывает.

## Как читать результат

1. **Строгий порядок измеряет одну последовательность.** У 0,80 из 241 пользователей цель — один и тот же курс, и в порядке по популярности среди кандидатов он стоит третьим: отсюда hit@1 0,01 при hit@3 0,84 у популярности. Правила и совместные записи ставят этот курс первым, поэтому выигрывают по NDCG@5 при одинаковом hit@5. Это реальный, но узкий сигнал: один переход между курсами, а не широкая картина.
2. **Совместные записи — лучший метод на всей выборке.** hit@5 0,73 против 0,69 у популярности и 0,64 у правил; NDCG@5 0,60 против 0,43 и 0,51. Интервалы hit@5 совместных записей и популярности соприкасаются, парное сравнение в пользу совместных записей: 85 пользователей против 49. Польза над популярностью, которой план требовал для признака «похожие курсы», на копии есть.
3. **Правила по темам помогают при смене курса внутри темы и мешают при смене темы.** Если цель делит тему с курсами входа, hit@5 0,99 против 0,88; если нет — 0,34 против 0,53, потому что кандидаты темы занимают пятёрку, а цель уходит в остаток по популярности. В продукте темы задаёт задача пользователя, а не история, поэтому в прототип этот результат переносится только для случая «пустая задача, есть история».
4. **Продолжение по редакционным связям почти не работает для курсов.** Цель есть в `recommended_next` последнего курса входа у 10 из 803 пользователей: связи между курсами редки, у 13 курсов из 37. Признак остаётся полезным для статей, где связей 3 457.
5. **Один курс на входе — типичный случай.** Таких 562 из 803; совместные записи и здесь лучше популярности, 0,77 против 0,73.

## Ограничения

- Результат относится к курсам: 26 доступных из 37, события только по курсам. На статьи и документы он не переносится, их просмотров в копии нет.
- 5 890 из 10 050 записей сделаны на курсы, недоступные сейчас; 759 из 1 562 пользователей исключены, потому что их цель недоступна. Оценённые 803 пользователя — те, чей следующий курс ещё открыт, выборка смещена в сторону действующих курсов.
- У 562 пользователей порядок событий не строгий, и случайная цель может предшествовать курсам входа. Группа со строгим порядком честнее, но в ней доминирует одна последовательность.
- Текста задачи, стадии, опыта и сферы у пользователей журнала нет, поэтому правила работали только темой, продолжением и историей. Это проверка части метода, а не всего подбора.
- Веса признаков по итогам не менялись. Оценка измеряет повтор поведения пользователей, а не пользу материалов и не влияние на покупки.

## Выводы для плана

1. Признак «похожие курсы» по совместным записям — кандидат для этапа 2 с подтверждённой на копии пользой над популярностью. Для него нужны журнал записей во время работы сервиса и фраза причины вроде «Пользователи этого курса часто записываются и на этот».
2. При пустой задаче и непустой истории не ограничивать кандидатов темами истории: на копии это снижает попадание для целей другой темы. Стартовая подборка с учётом совместных записей или популярности предпочтительнее.
