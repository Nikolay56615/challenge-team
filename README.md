# Подбор учебных материалов · прототип трека 1

Командная копия для совместной работы. Начните с [чек-листа проверки](docs/review.md). Рядом доступны [план](docs/PLAN.md), [дизайн](docs/design.md), [данные для сверки](docs/data.md) и [план презентации](docs/presentation.md).

Предприниматель описывает задачу своими словами и, по желанию, стадию бизнеса, опыт, формат и сферу. Сервис возвращает пять материалов в порядке пользы. У каждой карточки есть причина выбора, следующий шаг и пометка «Бесплатно» или «Платно». Рядом работает простой метод — подбор по совпадению темы. Режим сравнения показывает оба метода на одном профиле и одном каталоге.

Прототип работает без внешних сервисов, ключей и LLM. В комплекте только вымышленные данные: 23 материала и 10 тестовых профилей. Ссылки ведут на зарезервированный домен `example.org` и не являются адресами платформы.

В корне репозитория лежат папки `backend/` и `frontend/`, `Dockerfile`, файлы `compose.yaml` и `compose.data.yaml`, а также `.github/workflows/`. Команды ниже выполняются из корня, если не указана другая папка.

## Запуск через Docker

Нужен Docker с Compose v2, то есть с командой `docker compose`.

```bash
docker compose up --build
```

Интерфейс откроется на <http://localhost:8000>, документация API — на <http://localhost:8000/docs>. Порт опубликован только на `127.0.0.1`, поэтому сервис доступен лишь с этой машины. Остановить его можно клавишами Ctrl+C или командой `docker compose down`.

Другой порт на машине задаёт переменная `APP_PORT`. Внутри контейнера сервис всегда слушает 8000.

```bash
APP_PORT=8080 docker compose up --build
```

```powershell
$env:APP_PORT = "8080"; docker compose up --build
```

В PowerShell переменная действует до конца сеанса, убрать её можно командой `Remove-Item Env:APP_PORT`. Переменные можно задать и в файле `.env` рядом с `compose.yaml`: `docker compose` читает его в любой оболочке. Образец — [env.example](env.example), список переменных — в разделе «Переменные окружения».

Чтобы сервис был доступен другим машинам в доверенной сети, замените адрес `127.0.0.1` в строке `ports` файла `compose.yaml` на `0.0.0.0` или на адрес нужного сетевого интерфейса. Аутентификации в прототипе нет, поэтому в общей сети порт не открывайте.

Workflow [.github/workflows/docker-check.yml](.github/workflows/docker-check.yml) запускается при push, pull request и вручную. GitHub выполняет его, только если папка `.github/` лежит в корне репозитория. В нём два задания:

- `backend-tests` прогоняет тесты бэкенда на Python 3.12.
- `docker` собирает образ и проверяет его состав. В `/srv/app` лежат только `backend/app`, `backend/data`, `backend/requirements.txt` и `frontend/dist`. Задание проверяет отсутствие файлов `*.sqlite3` в образе, запускает контейнер, проверяет готовность, подбор для P01 и интерфейс в Chromium. В конце задание запускает контейнер с `compose.data.yaml` на JSON-каталоге из `backend/data` и проверяет, что `/api/health` сообщает источник `file`. При сбое задание выводит журнал контейнера.

## Запуск без Docker

Нужны Python 3.12 или новее и Node.js 22.12 или новее.

```powershell
# Windows PowerShell, из корня репозитория
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
cd ..\frontend
npm ci
npm run build
cd ..\backend
.venv\Scripts\python -m uvicorn app.main:app --port 8000
```

```bash
# Linux и macOS, из корня репозитория
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd ../frontend
npm ci
npm run build
cd ../backend
.venv/bin/python -m uvicorn app.main:app --port 8000
```

Бэкенд раздаёт собранный интерфейс из `frontend/dist`. Порт задаёт ключ `--port`, переменная `APP_PORT` здесь не действует. Остальные переменные из раздела «Переменные окружения» задаются в оболочке перед запуском: файл `.env` приложение не читает. Например, без демо-режима сервис запускается так:

```powershell
$env:DEMO_MODE = "false"; .venv\Scripts\python -m uvicorn app.main:app --port 8000
```

```bash
DEMO_MODE=false .venv/bin/python -m uvicorn app.main:app --port 8000
```

Для разработки с горячей заменой запустите бэкенд с `--reload`, а в `frontend` — `npm run dev`. Интерфейс откроется на <http://localhost:5173>, запросы к `/api` уйдут на порт 8000.

## Проверки

```bash
# из папки backend, в окружении .venv из раздела выше
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

В Windows вместо `.venv/bin/python` — `.venv\Scripts\python`.

Тесты проверяют порядок выдачи на тестовых профилях, соответствие причин фактическим признакам ранжирования, разбор запроса на наборе фраз, статусы при неполных сведениях, ошибки валидации и HTTP, правила ссылок, демо-режим, загрузчики JSON и SQLite на вымышленных данных и метрики на разметке релевантности `backend/tests/relevance.json`. `npm run build` в `frontend` проверяет типы TypeScript и собирает интерфейс.

Сквозные сценарии и проверка доступности используют Chromium из Playwright. Запустите приложение с собранным интерфейсом, тестовым каталогом и включённым демо-режимом. Из корня репозитория выполните:

```bash
npm --prefix evaluation/e2e ci
npm --prefix evaluation/e2e run install:browser
npm --prefix evaluation/e2e run check:ui
npm --prefix evaluation/e2e run check:a11y
```

На Linux для установки системных библиотек Chromium добавьте `-- --with-deps` к команде `install:browser`. По умолчанию проверки обращаются к `http://127.0.0.1:8000`. Другой адрес можно передать после `--`, например `npm --prefix evaluation/e2e run check:ui -- http://127.0.0.1:8080`. Снимки и JSON-отчёты сохраняются в `evaluation/e2e/.results/`. В GitHub Actions они доступны в артефакте `browser-checks` задания `docker`.

## Маршрут демонстрации

Чтобы открыть материалы по теме, перейдите в «Каталог» в хедере. На широком экране нажмите на тему в списке слева. На узком экране выберите тему в выпадающем списке и нажмите «Показать материалы темы». При возврате в «Подбор» доступны прежняя задача и её результаты.

1. Выберите в панели «Демо-режим» профиль P01 и нажмите «Подобрать материалы». Первые три карточки — чек-лист, видео и статья для новичка. У чек-листа в причине названа сфера «кафе и рестораны». Ниже — маршрут на первую неделю.
2. Выберите P02 и нажмите «Подобрать материалы». Первым стоит платный курс для растущего бизнеса с краткой пользой и кнопкой перехода. У платного вебинара нет кнопки перехода: ссылка не передана. Видео помечено «Вы уже открывали».
3. Включите «Сравнить с подбором по теме» и нажмите «Подобрать материалы»: появятся результаты обоих методов для P02. Выберите P01 и нажмите кнопку ещё раз. Подбор по теме у двух профилей одинаков, персональный различается.
4. Нажмите «Сбросить»: форма очистится, сравнение выключится. Затем нажмите «Подобрать материалы» с пустой формой. Появится стартовая подборка по темам и вопрос «С чего хотите начать?».
5. Выберите P05 с задачей «Хочу больше клиентов» и нажмите «Подобрать материалы». Появится вопрос «Уточните тему». Выберите «Продвижение»: выдача обновится сама и сузится до одной темы, форма сохранится.
6. Выберите P04 и нажмите «Подобрать материалы». Появятся честное сообщение об отсутствии материалов, выбор темы и стартовая подборка.
7. Снова выберите P01 и нажмите «Подобрать материалы». У первой карточки нажмите «Отметить изученным»: чек-лист уйдёт из пятёрки, наверх поднимутся его продолжения — статья и шаблон.
8. Остановите бэкенд и нажмите «Подобрать материалы». Появится сообщение об ошибке. Запустите бэкенд снова и нажмите «Повторить»: уйдёт тот же запрос, вводить данные заново не нужно. В Docker бэкенд останавливается командой `docker compose stop` и запускается командой `docker compose start`.

Все компоненты интерфейса и их состояния собраны на странице `/kit.html` — витрине UI-кита.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `APP_PORT` | Порт на машине пользователя для `docker compose`; внутри контейнера сервис слушает 8000 | `8000` |
| `CATALOG_SOURCE` | `synthetic`, `sqlite` или `file` | `synthetic`, с `compose.data.yaml` — `sqlite` |
| `CATALOG_PATH` | Путь к копии SQLite или к JSON в каноническом формате | пусто, с `compose.data.yaml` — `/data/catalog.sqlite3` |
| `CATALOG_SIGNALS_PATH` | Необязательная база признаков из названий и описаний | пусто, с `compose.data.yaml` — `/data/catalog-signals.sqlite3` |
| `CATALOG_MAPPING` | Файл соответствия для другой выгрузки, образец — `backend/data/mapping.example.yaml` | пусто |
| `LOCAL_DATA_DIR` | Папка с выгрузкой на машине пользователя, нужна только для `compose.data.yaml` | пусто |
| `DEMO_MODE` | Тестовые профили и режим сравнения: `true`, `false`, `1`, `0`, `yes`, `no`, `on` или `off` | `true` |
| `MAX_TASK_LENGTH` | Предел длины задачи, от 1 до 2000 символов | `300` |
| `LOG_LEVEL` | Уровень журнала приложения и uvicorn: `debug`, `info`, `warning`, `error` или `critical` | `info` |

Для `CATALOG_SOURCE`, `DEMO_MODE` и `LOG_LEVEL` регистр не важен. Недопустимое значение этих переменных или `MAX_TASK_LENGTH` останавливает запуск с сообщением, где названа переменная.

Приложение само не читает `.env`. С Docker переменные берутся из оболочки или из файла `.env` рядом с `compose.yaml`, образец — [env.example](env.example). Без Docker они задаются в оболочке. Журнал пишет код запроса, статус, число кандидатов и длительность, но не текст задачи.

## Своя выгрузка каталога

Для выданного PostgreSQL-бэкапа «Альфа-Курса» используйте [команду локального импорта](docs/data.md). Она подготавливает обе SQLite-базы для подключения через Compose.

Выгрузка платформы в SQLite подключается без изменения кода: `CATALOG_SOURCE=sqlite`, путь к базе — `CATALOG_PATH`, необязательная база признаков из названий и описаний — `CATALOG_SIGNALS_PATH`. Статусы публикации, группы тем, рубрики, отрасли, метки уровня и стадии, типы доступа и разбор длительности задаёт файл соответствия. Образец — `backend/data/mapping.example.yaml`, свой файл указывается в `CATALOG_MAPPING`. База открывается только на чтение. Поле без источника отключает связанный признак, список отключённых признаков и сводка покрытия видны в `GET /api/health`.

Каталог в JSON подключается через `CATALOG_SOURCE=file`, формат файла — как у `backend/data/catalog.synthetic.json`.

В Docker папку с данными подключает наложение `compose.data.yaml`. Оно монтирует папку `LOCAL_DATA_DIR` в контейнер как `/data` только на чтение и по умолчанию включает источник `sqlite` с файлами `catalog.sqlite3` и `catalog-signals.sqlite3` из этой папки:

```bash
LOCAL_DATA_DIR=/путь/к/папке/с/выгрузкой docker compose -f compose.yaml -f compose.data.yaml up --build
```

```powershell
$env:LOCAL_DATA_DIR = "D:\путь\к\папке\с\выгрузкой"; docker compose -f compose.yaml -f compose.data.yaml up --build
```

В переменных указываются пути внутри контейнера. Для JSON задайте `CATALOG_SOURCE=file` и `CATALOG_PATH=/data/<имя файла>.json`, для своего файла соответствия — `CATALOG_MAPPING=/data/<имя файла>`. Эти строки удобно записать в `.env`. Без Docker в тех же переменных указываются пути на диске.

Папка в образ не попадает. В Linux контейнер работает от пользователя с uid 10001, и ему нужны права на вход в папку и чтение файлов. Права можно дать всем или только этому пользователю, например: `setfacl -R -m u:10001:rX <папка>`. Без них каталог не откроется, и `GET /api/health` ответит 503.

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Готовность, источник и версия каталога, отключённые признаки, сводка покрытия |
| `GET /api/meta` | Источник каталога и число доступных материалов, все темы с доступными материалами и подписи уточнений |
| `GET /api/profiles` | Тестовые профили, только при включённом `DEMO_MODE` |
| `POST /api/recommend` | Подбор: `method` = `personal` или `baseline` |
| `POST /api/compare` | Оба метода на одном запросе и число изменившихся позиций |

После подбора по задаче или теме можно ограничить выдачу форматом и доступом. Оба POST-эндпоинта принимают необязательный объект `filters`, например `{"format":"document","access":"open"}`. `filter_options` содержит варианты из исходных кандидатов каждого метода, а `total_candidates` считает материалы с учётом фильтров. Если фильтры исключили все совпадения, ответ сохраняет статус подбора, возвращает пустой `items` и предлагает сбросить фильтры в интерфейсе.

Пример запроса:

```json
{
  "task": "Хочу начать продвигать свою кофейню, с чего начать?",
  "stage": "start",
  "experience": "none",
  "industry": "horeca",
  "history": [],
  "limit": 5
}
```

Ошибки API приходят в одном виде: `{"error": {"code": "validation_error", "message": "Запрос длиннее 300 символов", "details": [...]}}`. В `details` не больше 10 записей. Коды: 422 — неверный запрос, 413 — тело запроса больше 64 КБ (`payload_too_large`), 404 — неизвестный путь (`not_found`), 405 — неверный метод (`method_not_allowed`, с заголовком `Allow`), 503 — каталог не загружен, 500 — прочие сбои без внутренних подробностей. Статические файлы интерфейса отвечают стандартными кодами HTTP без этого формата, например 416, если диапазон в заголовке `Range` выходит за размер файла.

## Как устроен подбор

- **Подбор по теме** находит темы в задаче по словарю основ и сортирует материалы темы по популярности.
- **Совпадения по словам в SQLite.** Персональная выдача поднимает совпадения по ключевым словам в названии, затем в коротком описании курса. В запросе без распознанной темы уверенное совпадение в названии позволяет найти материал по всему каталогу. При выбранной теме поиск ограничен её материалами. `rank` отражает итоговый порядок, `score` — баллы персонального ранжирования внутри групп. [Офлайн-проверка поиска](evaluation/search-relevance.md)
- **Персональный подбор** складывает вклады признаков: тема, признак из текста материала, стадия, уровень, сфера, формат, длительность для новичка, продолжение по редакционным связям и история. Пройденное и просмотренное опускается, начатый курс поднимается. В пятёрке не больше трёх материалов одного формата, если другой формат близок по оценке.
- **Причина** собирается из признаков с наибольшим вкладом, две–три фразы. Пометки истории показываются бейджами.
- **Неполные сведения.** Пустая задача даёт стартовую подборку. Задача на две темы даёт уточнение. Тема вне каталога даёт честное сообщение и выбор темы.
- **Понятие без темы.** Если задача называет понятие, но не тему, например «Какую CRM выбрать», персональный подбор берёт материалы с этим понятием из любых тем. Если таких нет, показывается честное сообщение. Подбор по теме понятий не различает и в этом случае предлагает стартовую подборку.
- **Узкий запрос.** Для словарных запросов о лицензировании, продаже алкоголя, сертификации и визах, в которых нет отдельного понятия вроде CRM, сервис ищет все распознанные признаки в одном названии. Персональный метод ищет по всему каталогу доступных материалов, подбор по теме ограничивается распознанными темами. Поэтому совпадение только в описании материала может быть пропущено. Если подходящих названий нет, сервис сообщает об этом и предлагает выбрать тему. Ручной выбор включает обычный подбор по теме.

Веса — гипотеза первого прототипа. Тесты проверяют порядок на профилях, а не сами числа.

## Структура

```
backend/
  app/            FastAPI: api/ — HTTP, catalog/ — источники и словарь, ranking/ — подбор и объяснения
  data/           синтетический каталог, профили, фикстуры, образец файла соответствия
  tests/          pytest
frontend/
  src/kit/        UI-кит: базовые компоненты; токены и стили в src/styles/
  src/components/ компоненты экрана
  kit.html        витрина кита
Dockerfile        образ: сборка интерфейса на Node, рабочий образ на Python
compose.yaml      запуск через Docker
compose.data.yaml наложение для своей выгрузки каталога
env.example       образец .env для docker compose
.github/workflows/docker-check.yml   тесты бэкенда и проверка образа в CI
```

## Ограничения

- Демонстрация идёт на синтетическом каталоге. Прогон на копии реальной выгрузки выполняется только локально у автора: копия не входит в комплект.
- Влияние на конверсию в покупку и активные дни не измерено. Для этого нужен онлайн-эксперимент с телеметрией.
- Аутентификации нет: прототип рассчитан на локальный запуск.
