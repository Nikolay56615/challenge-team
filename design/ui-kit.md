# UI-кит трека 1

Кит фиксирует токены и компоненты интерфейса подбора учебных материалов. Он собран из утверждённого [макета](track1/mockup.html) и [спецификации интерфейса](../docs/PLAN.md#5-спецификация-интерфейса). Фронтенд строится только из компонентов кита. Если экрану чего-то не хватает, сначала дополняется кит, затем экран.

Визуальный язык синхронизирован с проектом `shift-frontend-web`: тёплая палитра, шрифт Onest, крупные радиусы, сегментные вкладки. Разметка, классы, поведение и офлайн-работа не менялись; акцент затемнён ради контраста.

| Что | Где |
| --- | --- |
| Токены | [frontend/src/styles/tokens.css](../frontend/src/styles/tokens.css) |
| Стили компонентов | [frontend/src/styles/kit.css](../frontend/src/styles/kit.css) |
| React-компоненты | `frontend/src/kit/` — базовые, `frontend/src/components/` — компоненты экрана |
| Витрина всех компонентов и состояний | страница `kit.html` фронтенда: `/kit.html` при `npm run dev` и в собранном приложении |
| Состояния экрана целиком | [макет](track1/mockup.html) и снимки в [preview/](track1/preview/) |

## 1. Правила

1. Экран собирается из компонентов разделов 3 и 4. Цвета, шрифты, отступы и радиусы берутся из токенов. Стили экрана задают только сетку компоновки и тоже используют токены.
2. Интерактивные элементы нативные: `button`, `a`, `input type="radio"`, `input type="checkbox"`, `select`, `textarea`, `details`. ARIA-роли добавляются там, где нативного элемента нет, — во вкладках сравнения.
3. Высота любого интерактивного элемента не меньше 44 px. Фокус с клавиатуры виден всегда: кольцо 2 px цвета `--color-focus` с отступом 2 px.
4. Цвет не единственный носитель смысла. Платность, пометки истории, выбранный чип и ошибка дублируются текстом или начертанием.
5. Подписи тем, стадий, опыта, форматов и сфер приходят из `GET /api/meta` и из ответа API. Ключевые строки экрана перечислены в [PLAN.md, 5.7](../docs/PLAN.md#57-тексты-интерфейса). Компонент не придумывает подписи данных.
6. Текст из API выводится как текст. `dangerouslySetInnerHTML` не используется.

### 2.4 Компоновка

Экран — контейнер запросов `screen`. До 800 px — одна колонка, форма над результатами, поля экрана 24 px. От 800 px — две колонки: форма шириной 360 px слева, результаты справа, поля 24 px по бокам и 32 px сверху, зазор 32 px. Колонка результатов не шире 760 px и прижата влево: на широких экранах строка не растягивается на всю ширину. Порог задан числом в `@container screen (min-width: 800px)`: CSS не допускает переменную в условии. Порядок чтения совпадает с визуальным порядком.

## 3. Базовые компоненты

Все компоненты экспортируются из `frontend/src/kit/index.ts`. Пропсы ниже — обязательный минимум. Остальные нативные атрибуты, включая `id`, `aria-*` и `data-*`, передаются корневому элементу, а у полей — самому элементу управления. `Button`, `Card` и `StatusLine` принимают `ref` для переноса фокуса.

| Компонент | Разметка и классы | Варианты и состояния | Доступность |
| --- | --- | --- | --- |
| `Button` | `button.btn` + `btn--primary`, `btn--secondary`, `btn--outline`, `btn--link`, размер `btn--sm` | Обычное, наведение, фокус, `disabled`. Занятое состояние меняет подпись: «Подобрать материалы» → «Подбираем…» | `type="button"` по умолчанию. Занятая основная кнопка получает `aria-disabled="true"`, а не `disabled`: фокус остаётся на ней |
| `ButtonLink` | `a.btn` с теми же классами | Внешняя ссылка открывается в новой вкладке | `rel="noopener noreferrer"`, скрытая подпись «откроется в новой вкладке». Только `http` и `https` из ответа API |
| `ChipGroup` | `fieldset.field` > `legend` + `div.chip-group` > `label.chip` > `input[type=radio].visually-hidden` + `span.chip__label` | Выбран, не выбран, фокус, `disabled`. Повторное нажатие на выбранный чип снимает выбор: мышью, пробелом, а в режиме `manual` и клавишей Enter. Режим `activation`: `auto` — поля формы, `manual` — выбор запускает запрос | `auto` — нативная радиогруппа: стрелки переключают, Tab входит в группу. `manual` — стрелки только переносят фокус, выбирают щелчок, пробел и Enter: движение по вариантам не отправляет запрос (WCAG 3.2.2). Имя группы получает уникальный суффикс. Выбранный чип отличается рамкой, фоном и начертанием 600 |
| `Badge` | `span.badge` + `badge--free`, `badge--paid`, `badge--flag`, `badge--topic` | Нейтральный по умолчанию | Текст обязателен, цвет только дублирует смысл |
| `Panel` | `section.panel`, вариант `panel--subtle` | — | Заголовок панели связан через `aria-labelledby` |
| `Card` | `article.card` | — | `aria-label="Позиция N"` |
| `Banner` | `div.banner` + `banner--info` или `banner--error`; `banner__title`, `banner__text`, слот действий | Информационный, ошибка. Основная кнопка в баннере сохраняет свою ширину и на узком экране | Информационный — `role="status"`, ошибка — `role="alert"`. Фокус баннер не переносит, это делает экран (раздел 4.1) |
| `TextAreaField` | `div.field` > `label.field__label` + `textarea.textarea` + `div.field__error` и `div.field__hint` со счётчиком | Пусто, заполнено, `disabled`, ошибка. Счётчик «N из 300 символов» виден и при ошибке | `aria-describedby` на подсказку и ошибку, `aria-invalid` при ошибке. Ошибка валидации показывается под полем, а не баннером |
| `SelectField` | `div.field` > `label` + `select.select` + `div.field__hint`, компактный вариант `select--compact` | Пустое значение «Не указана» или «Не выбран». Компактный список занимает ширину содержимого | Нативный `select`: роль `combobox` и управление стрелками без доработок. Подсказка связана через `aria-describedby` |
| `Checkbox` | `label.checkbox` > `input[type=checkbox]` + текст | Отмечен, не отмечен, `disabled` | Цвет отметки через `accent-color` |
| `Tabs`, `TabPanel` | `div.tabs[role=tablist]` > `button.tab[role=tab]`; панель `div[role=tabpanel]` | Выбрана: мягкая акцентная заливка с рамкой на нейтральном треке | Стрелки влево и вправо, Home, End, подвижный `tabindex`. Используются только на узком экране сравнения |

## 4. Компоненты экрана

Компоненты экрана лежат в `frontend/src/components/` и собираются только из базовых.

| Компонент | Из чего собран | Данные API | Состояния и правила |
| --- | --- | --- | --- |
| `TaskForm` | `Panel`, заголовок h1, `TextAreaField`, `RefinementFields`, `Button` primary и link | `task`, `catalog` из `GET /api/meta` | Под заголовком виден источник каталога. Для локальной выгрузки указано число доступных материалов. Кнопка активна при любом вводе, в том числе пустом. При загрузке поля заблокированы, подпись «Подбираем…». Данные не очищаются при загрузке и ошибке. «Сбросить» очищает форму, историю сеанса, выдачу, тестовый профиль и флажок сравнения |
| `RefinementFields` | `Disclosure` «Уточнения — необязательно», три `ChipGroup`, `SelectField` | `stage`, `experience`, `format_pref`, `industry`; подписи из `/api/meta` | Свёрнут по умолчанию. Одиночный выбор, повторное нажатие снимает выбор |
| Темы каталога и `TopicPicker` | Список кнопок на широком экране, `SelectField` и кнопка на узком | `topics` из `/api/meta` или `clarification.options` | Раздел «Каталог» открывает тему с пустой задачей и хранит её выдачу при переходах через хедер. Выбор из выпадающего списка подтверждается кнопкой «Показать материалы темы». В состояниях `cold` и `none` в разделе «Подбор» список заменяет чипы при числе тем больше семи |
| `DemoPanel` | `Panel` subtle, `SelectField` compact, `Checkbox` | `GET /api/profiles`, `profile_id`, история профиля | Только при включённом `DEMO_MODE`. Выбор профиля заполняет форму и историю сеанса, отменяет текущий запрос и убирает прежнюю выдачу. «Не выбран» очищает историю сеанса и тему уточнения, текст формы сохраняет |
| `StatusLine` | базовый | `message` | Загрузка: «Подбираем материалы…». Строка всегда в дереве: при сравнении, пустой выдаче и ошибке она визуально скрыта, но озвучивает итог. Для сравнения, если оба метода вернули `strong` или `weak`: «Сравнение готово. Изменились позиции: N из M.» Если материалов не нашёл один метод, строка называет его: «Сравнение готово. Подбор по теме не нашёл материалов по запросу.» Если оба: «Сравнение готово. Ни один метод не нашёл материалов по запросу.» При пустой задаче: «Сравнение готово. Без задачи оба метода показывают стартовую подборку.» |
| `StateBanner` | `Banner`, `ChipGroup` с `legendHidden` и `activation="manual"`, `Button` link и primary `sm` | `clarification`, ошибка запроса | Слабое совпадение: вопрос, чипы тем, «Оставить как есть». Пока выдача по выбранной теме загружается, баннер виден и заблокирован. Новая отправка формы убирает его, «Оставить как есть» скрывает до следующей отправки. Тема из баннера действует, пока текст задачи не изменился. Ошибка: текст ответа или «Сервис не ответил», «Повторить» отправляет тот же запрос |
| `ResultList` | `StatusLine`, заголовок h2 со счётчиком выдачи, `MaterialCard`, `RouteBlock`, `Button` secondary | `items`, `route`, `total_candidates` | «Показать ещё N» запрашивает до 10 позиций с теми же параметрами. При достижении лимита и наличии дополнительных совпадений появляется подсказка об уточнении задачи |
| `MaterialCard` | `Card`, `RankMarker`, `Badge`, `KeyValue`, `ButtonLink`, `Button` link | `items[]` | Анатомия ниже |
| `RouteBlock` | `section.route`, заголовок h2 в стиле `kv__label`, нумерованный список | `route` | Только при статусе `strong` и стадии idea или start |
| `EmptyState` | `Panel`, заголовок h2, `ChipGroup` тем с `activation="manual"`, компактные `MaterialCard` | `status` `none` или `cold`, `clarification`, `items`, `total_candidates` | При `none` — сообщение о пробеле. При `cold` — вопрос «С чего хотите начать?» без сообщения о пробеле. Видны три карточки, остальные по кнопке «Показать все N», где N = min(`total_candidates`, 10). Если сервер вернул меньше N карточек, кнопка повторяет запрос с `limit` 10. Раскрытие сохраняется при повторах того же запроса |
| `CompareView` | `Panel`, `Tabs` на узком экране, две колонки на широком, компактные `MaterialCard` | `POST /api/compare`: `status`, `message` и `items` каждого метода, `diff` | Один профиль, один каталог, два метода. На широком экране вкладок нет, колонки озаглавлены h3: «Подбор по теме» и «Персональный подбор». Колонка со статусом `none`, `cold` или `empty` вместо карточек показывает абзацем сообщение ответа, например «Подбор по теме не нашёл тему в запросе „Какую CRM выбрать“.» Её карточки собраны в группу `div.starter` с `role="group"`. Подпись группы «Стартовая подборка» видна и оформлена абзацем в стиле `kv__label`, а не заголовком. Для каждого метода показан свой счётчик карточек. Темы берутся из карточек в порядке API. Вывод «Изменились позиции: N из M.» стоит в верхней панели под заголовком и появляется, только если обе колонки `strong` или `weak`: стартовую подборку с выдачей по запросу не сравнивают. Выбранная вкладка сохраняется при повторах того же запроса |
| `IntroPanel` | `Panel`, список | — | Начальное состояние: «Что вы получите» и примеры задач |

Анатомия `MaterialCard`:

1. Номер позиции и название h3.
2. Бейджи в порядке отображения — до двух тем из `topic_labels`, формат, длительность, доступ, уровень при наличии и пометки истории.
3. Описание курса из `course_details.description`. Заполненные разделы «Кому подойдёт» и «Результаты обучения» находятся в свёрнутом блоке «Подробнее о курсе». Для платной карточки с пустым описанием используется `short_benefit`, если оно заполнено.
4. «Почему подходит»: фразы `reasons` одним абзацем.
5. «Следующий шаг» из `next_step` при наличии разрешённого адреса.
6. Действия. При разрешённом адресе отображается кнопка перехода. Без адреса доступно «Скопировать название», результат озвучивается без перемещения фокуса. Если все видимые карточки без ссылок, пояснение показывается один раз над списком. В смешанной выдаче пояснение показывается на карточке без адреса. «Отметить изученным» доступно до появления пометки «Пройдено».

В компактной карточке для сравнения и стартовой подборки видны описание и подробности курса, а причины идут под подписью «Почему». Стартовая подборка показывает собственный счётчик видимых карточек.

API отдаёт `reasons`, `next_step` и `short_benefit` фразами без конечной точки. Карточка выводит их предложениями: функция `toSentence` в `src/format.ts` ставит точку, если конечного знака нет.

Длительность выводится так: до 120 минут — «N мин», ровные часы — «N ч», иначе «N ч M мин».

### 4.1 Фокус и запросы

| Ситуация | Куда идёт фокус |
| --- | --- |
| Запрос отправлен из выдачи: тема, «Показать ещё», «Отметить изученным», «Повторить» | На строку состояния, которая видна во время загрузки |
| Форма отправлена кнопкой «Подобрать материалы» | На заголовок со счётчиком при `strong` или `weak`, h2 `CompareView` или `EmptyState`. При ошибке — на «Повторить» |
| Ответ со статусом `strong` или `weak` | Остаётся на строке состояния |
| Ответ сравнения, `none`, `cold`, пустая выдача | На заголовок h2 `CompareView` или `EmptyState` с `tabIndex=-1` |
| Ошибка | На кнопку «Повторить» |
| «Показать ещё N», «Показать все N» | На первую новую карточку |
| Ошибка 422 по полю задачи | На поле, текст ошибки под ним |

Если пользователь сам перевёл фокус во время загрузки, экран его не забирает. Ответ на устаревший запрос отбрасывается. Повторный щелчок во время загрузки второй запрос не отправляет. Запрос прерывается через 15 секунд. Таймаут и ответ 5xx без JSON показываются как «Сервис не ответил».

## 5. Отличия от макета

Кит перенимает визуальный язык `shift-frontend-web`, но сохраняет структуру и поведение макета. Изменения внесены ради доступности, устойчивости вёрстки и точности состояний.

| Что | В макете | В ките | Почему |
| --- | --- | --- | --- |
| Кольцо фокуса | 3 px `#8FB0FF`, контраст 2,14 | 2 px `--color-focus` `#C41230`, контраст 6,04 | Требование 3:1 для индикатора фокуса |
| Рамки поля задачи, списков, флажка | `#DDE3EA`, контраст 1,29 | `--color-line-strong` `#8B7C80`, контраст 3,97 | Граница поля ввода должна различаться с контрастом 3:1 |
| Высота чипов и кнопок `sm` | 32–37 px | не меньше 44 px | Минимальная цель нажатия по PLAN.md, 5.5 |
| Чипы, список сфер, флажок | `span` с ролями `radio` и `combobox` | Нативные `input` и `select` | Клавиатура и вспомогательные технологии без доработок |
| Выбранная вкладка | Фон и цвет | Мягкая заливка `--color-accent-soft`, рамка `--color-accent` и текст `--color-accent-ink` на нейтральном треке | Выбор различим не только цветом: меняются фон, рамка и начертание; контраст текста 8,29:1, сплошной акцент остаётся за главным действием |
| Левая колонка | Прилипает при прокрутке | Обычный поток | Высокая форма обрезалась на экранах ниже 900 px |
| Заголовок пустой выдачи | 18 px | 20 px, как другие h2 | Одна ступень шкалы для заголовков второго уровня |
| Отступ между группами «Уточнений» | Почти нет: подпись группы прижата к чипам | 12 px через `disclosure__body` | Группы полей читаются отдельно |
| Строка «Уточнения» | «необязательно» в середине строки | «Уточнения» и «необязательно» слева, стрелка справа | Пометка относится к подписи |
| Подпись «Тестовый профиль» | В строке со списком | Над списком; описание профиля не дублируется | Нативный `select` не переносит длинные подписи профилей |
| Пояснение сравнения | «Слева… справа…», «бейзлайн», вводный абзац и подзаголовки колонок | Только заголовок сравнения и вывод «Изменились позиции» в верхней панели | Вводный абзац и подзаголовки повторяли друг друга и метаданные карточек |
| Колонка сравнения без выдачи по запросу | Подзаголовок о порядке и итог под колонками есть всегда | Сообщение ответа вместо карточек, подпись «Стартовая подборка» над карточками, «Изменились позиции» в верхней панели только при двух выдачах по запросу | Стартовая подборка не выдаётся за подбор по теме, а позиции разных подборок не сравниваются |

## 6. Витрина, проверка и Figma

Витрина `kit.html` показывает каждый базовый компонент во всех вариантах и состояниях и каждую карточку на вымышленных данных из синтетического каталога. Перед изменением кита и после него витрину проверяют на ширине 390 и 1120 px и проходят клавиатурой.

Figma служит зеркалом для просмотра и комментариев. Витрина и экраны переносятся в приватный черновик захватом страницы через Figma MCP. На тарифе Starter захват не расходует месячный лимит чтения. Источник правды — этот документ и код кита. Ссылка на черновик передаётся в чате и в документы не записывается.

Состояние зеркала на 10 ноября 2026 года: в черновике макет из `design/track1/mockup.html` и две страницы витрины `kit.html` — от 9 ноября и актуальная от 10 ноября, после изменения сравнения. Ориентироваться нужно на последнюю. Захват делается с копии страницы во временной папке: в копию добавляется скрипт захвата, а код приложения и его CSP не меняются. После изменения кита витрину переносят заново новым захватом.

## 7. Как менять кит

1. Опиши, чего не хватает экрану, и проверь, нельзя ли собрать это из существующих компонентов.
2. Дополни этот документ: токен или компонент, варианты, состояния, доступность.
3. Реализуй изменение в `tokens.css`, `kit.css` и `src/kit/`, добавь его на витрину.
4. Проверь контраст новых пар, клавиатуру и ширину 390 и 1120 px.
5. Только после этого используй компонент на экране.
