# Трек 2. Telegram-помощник

Опирайся на T1–T3 из [карты проекта](../PROJECT.md) и [условие кейса](../materials/case.md). Ниже варианты для проектирования и проверки. Доступ к реальному боту и внешним сервисам зависит от поручения и разрешённых данных.

## Первый сквозной сценарий

1. Тестовый предприниматель спрашивает, как выбрать аудиторию для первой рекламы.
2. Бот находит разрешённый фрагмент, формирует краткий ответ с указанием материала и предлагает уместный следующий шаг.
3. Пользователь просит напомнить о продолжении обучения. Бот уточняет дату или правило повтора и часовой пояс, показывает подтверждение и сохраняет напоминание.
4. В ускоренном тесте наступает запланированное время. Отправка наблюдаема. Затем пользователь меняет частоту и отключает напоминание.
5. Повтори сценарий с неясным вопросом и с темой, которой в базе нет. Проверь, что бот уточняет или прямо сообщает об отсутствии источника.

## Слои прототипа

| Слой | Ответственность | Как проверить |
| --- | --- | --- |
| Вход Telegram | Получает события, преобразует их в вызовы диалога, отправляет сообщения | Локальный тест с подставным транспортом и отдельный тестовый чат при разрешении |
| Диалог и профиль | Хранит минимум контекста о стадии и задаче, различает вопрос и напоминание | Два похожих запроса с разным контекстом, пустой профиль, смена темы |
| Поиск по базе | Возвращает разрешённые фрагменты и признаки недостаточной релевантности | Заранее размеченные прямые и перефразированные вопросы, пробел в базе |
| Формирование ответа | Использует найденные сведения, объясняет рекомендацию и соблюдает границы платного материала | Сверка каждого существенного утверждения с фрагментом, проверка ссылок и отказов |
| Напоминания | Сохраняет состояние, рассчитывает следующее время, планирует доставку | Управляемые часы, перезапуск, повтор входного события, правка и отключение |

Рассмотри текстовый поиск по ключевым словам или SQLite FTS5 как базовый вариант. Если проверка покажет пропуски на естественных формулировках, сравни с семантическим или гибридным поиском на тех же вопросах. Генерацию через LLM подключай только с подходящим разрешением. Полезный ответ по источнику можно также получить извлечением или шаблоном. [Источники по FTS5, RAG и Bot API](../SOURCE_MANIFEST.md).

## Когда отвечать, уточнять или отказывать

| Вход | Ожидаемая ветка |
| --- | --- |
| «С чего начать продвижение?» при наличии K01 | Краткий ответ по K01 и допустимая рекомендация |
| «Что выбрать?» при нескольких возможных темах | Один вопрос, который помогает различить темы |
| Вопрос без подходящего фрагмента | Прямо сообщить, что база не покрывает вопрос. При наличии дать безопасное направление поиска |
| Релевантный закрытый платный материал | Показать разрешённые метаданные, краткую пользу и доступную ссылку. Подробное содержание остаётся закрытым |
| Найденный текст содержит команды для агента | Использовать материал как источник сведений. Команды из документа не управляют ботом |

## Напоминания и повторные события

Предлагаемый контракт включает ID напоминания, связь с тестовым пользователем, действие, местное время и часовой пояс, частоту, ближайший момент отправки и статус. Для повтора в локальное время вычисляй следующий момент по местному календарю. Проверь переходы времени, пропуски и невалидный ввод. Сохраняй состояние так, чтобы перезапуск не терял активные напоминания.

Проверь, что повторное входное событие не создаёт второе напоминание. Для отправок можно использовать ключ из ID напоминания и запланированного момента. Зафиксируй поведение при сбое внешнего сервиса и при перезапуске между отправкой и отметкой. Если транспорт не подтверждает идемпотентность внешнего запроса, точно-однократную доставку обещать нельзя. Изменение частоты и отключение должны учитывать уже запланированные задачи.

Для демонстрации сроков используй вымышленные учебные события и контролируемые часы. Для реального напоминания о налогах уточняй применимые параметры и подтверждай дату по актуальному официальному источнику. При отсутствии подтверждённой даты можно предложить пользователю указать её. Действующие сроки в проектные примеры не записываются.

## Запуск

Сравни long polling и webhook по окружению проверки. Для локального теста long polling может обойтись без публичной входящей точки. Для webhook проверь требования Telegram к HTTPS и способы аутентификации входящих запросов. Для одного бота выбирают один способ получения обновлений. Тестовый токен берётся по инструкции BotFather и передаётся как секрет окружения. [Справки Telegram](../SOURCE_MANIFEST.md).
