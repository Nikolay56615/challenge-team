# Получение и подготовка данных

Для трека 1 начни с [описания локальной SQLite-копии](../docs/data-description.md). В ней есть каталог, справочники и взаимодействия. Для демонстрации используй вымышленные профили. Для проверки загрузки и выдачи можно читать базу из явно указанного пути в разрешённом локальном запуске. Не встраивай её в образ, общедоступный архив или внешний сервис.

## Когда есть только условие

В приложении 1 исходного кейса описана отдельная выгрузка. Попроси у пользователя или владельца данных разрешённую копию и словарь полей. Для трека 2 также нужны материалы, по которым разрешено отвечать. Доступность каталога и наличие полнотекстовой базы проверяются отдельно. [Каталог источников](../SOURCE_MANIFEST.md).

До получения данных можно отрабатывать поведение на синтетическом корпусе. Такой прогон подтверждает логику на выбранном примере. Качество покрытия реальных запросов, структуру исходной выгрузки и продуктовый эффект предстоит проверять отдельно.

## Приём разрешённой копии

1. Сверь назначение, формат файлов, словарь полей и разрешённые операции. Уточни, какие данные можно обрабатывать локально и какие поля можно передавать внешним API.
2. До импорта выбери рабочий путь с нейтральным именем и исключи закрытые входы из Git, Docker-контекста и комплекта сдачи. Привязка приложения к исходным личным путям запрещена.
3. Прочитай схему и разрешённый небольшой образец. Для таблиц проверь кодировку, типы, пустые значения, уникальность ключей, дубликаты и связь событий с каталогом. Для документов проверь пригодность текста, заголовки, границы фрагментов и уровень доступа.
4. Сделай рабочий контракт. Для каждого используемого поля укажи источник, тип, обязательность, правило нормализации и поведение при пропуске. Явно отдели поля, которые присутствуют в источнике, от вычисляемых.
5. Убери лишнее. Используй минимальные признаки, обезличенные или синтетические ID, разрешённые краткие описания и ссылки. Замена прямых ID сама по себе сохраняет риск идентификации по событиям и свободному тексту. Не переноси реальные строки в документацию и тестовые примеры.
6. Проверь, что после преобразования сохранились допустимые связи и сценарии. Запиши агрегированные результаты и ограничения в [каталоге](../SOURCE_MANIFEST.md) и ближайшее действие в [состоянии](../CURRENT.md).

Если предполагаемое поле отсутствует, выбирай явный запасной режим. Примеры — ранжирование без истории, краткая подборка с необязательным уточнением, ответ об отсутствии источника, показ карточки без ссылки. Для платных материалов не подставляй вымышленные адреса и не раскрывай полный текст.

## Синтетические контракты

Ниже примеры локальных входов. Имена полей выбраны для демонстрации и могут отличаться от реальной схемы.

| Сущность | Пример | Что проверить |
| --- | --- | --- |
| Карточка каталога | `M01` · продвижение · старт · чек-лист · бесплатно | Совпадение темы, объяснение, показ следующего шага |
| Вторая карточка той же темы | `M02` · продвижение · рост · продвинутый курс · платно | Бейзлайн и персонализация различаются, платная карточка выдаёт краткое описание |
| Профиль | `P01` · запуск · вопрос о первом продвижении · история отсутствует | Холодный старт без обязательной анкеты |
| Событие | `P02` · `M01` · просмотр · порядковый номер 1 | Соединение по ключу, обработка пропусков и повторов |
| Фрагмент базы | `K01` · «Для первой рекламной гипотезы выберите аудиторию и одно измеримое действие» · публичный тестовый фрагмент | Поиск по перефразированному вопросу и источник ответа |
| Настройка напоминания | `N01` · тестовый профиль · местное время 09:30 · еженедельно · включено | Расчёт следующего события, изменение частоты, отключение |

Для ручного набора добавь пустой профиль, неизвестную тему, дубль материала, отсутствующую ссылку, закрытый фрагмент, неоднозначный вопрос и повтор одного входного события. Привяжи каждую запись к проверяемому сценарию и ожидаемому поведению. Для времени подставляй тестовый пояс, выбранный для сценария.

## Минимальная запись об импорте

Достаточно перечислить логические сущности, число пригодных записей по каждой, пропуски в обязательных полях, проблемы связности, отброшенные классы данных, ограничения доступа и покрываемые сценарии. Пути — только относительные. В рабочих логах и Markdown оставляй агрегаты и тестовые примеры.
