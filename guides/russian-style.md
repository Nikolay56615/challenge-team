# Редактура русского текста проекта

Процедура предназначена для документации, отчётов, слайдов и речи этого кейса. В Claude Code её можно вызвать через [`/translator`](../.claude/skills/translator/SKILL.md). Все шаги и примеры доступны в проекте.

## Выбери режим

| Задача | Действие |
| --- | --- |
| Пишешь новый русский текст | Один раз перечитай черновик перед выдачей. Удали пустые подводки, повторы, канцелярит и выводы без опоры на данные |
| Пользователь просит найти признаки шаблонного текста | Приведи конкретный фрагмент, объясни, что мешает чтению, и предложи локальное действие. Сохрани исходник |
| Пользователь просит точечную правку | Исправь указанный фрагмент или оборот. Проверь связность со смежными предложениями |
| Пользователь просит полную вычитку | Сначала прочитай текст целиком, затем правь проблемные места и сверяй смысл. Если есть образец речи автора, учитывай его ритм и словарь |

## Что проверять

- **Пустая подводка.** Удали «стоит отметить, что», «давайте разберёмся», «подводя итог». Начни с факта, действия или результата.
- **Канцелярит.** Замени «осуществить запуск» на «запустить», «в целях проверки» на «для проверки». Сохрани точный термин, если он обозначает механизм или требование.
- **Повтор и искусственное усиление.** Оставь каждый самостоятельный факт один раз. Проверь, сообщают ли обе части конструкции «не просто …, а …» разные сведения. Если противопоставление пустое, оставь содержательную часть.
- **Похвала без факта.** Удали «комплексное решение», «выход на новый уровень», «высокое качество». Если в исходнике есть наблюдение, сформулируй его с условиями проверки.
- **Следы копирования из чата.** Убери обращения и предложения доработок, попавшие в документ, а также технические метки интерфейса. Для ссылки с меткой проверь исходный адрес и сохрани действительную ссылку на источник. Авторские цитаты и буквальные строки проверяй отдельно.
- **Разметка и ритм.** Оставь заголовки и списки, когда по ним удобно найти шаг. Дели длинную фразу там, где она содержит два самостоятельных утверждения. Одиночное тире, точный повтор или привычная для автора фраза сами по себе правки не требуют.

## Примеры по кейсу

Примеры вымышлены и показывают редактуру формулировок. Фактическое состояние записано в [CURRENT.md](../CURRENT.md).

| Где | Черновик | После вычитки |
| --- | --- | --- |
| README | «В целях проверки необходимо осуществить запуск приложения и ввести задачу пользователя». | «Запустите приложение и введите задачу пользователя». |
| Слайд о рекомендациях | «Стоит отметить, что система не просто выдаёт список, а показывает причину каждой рекомендации». | «Рядом с каждой рекомендацией система показывает причину выбора». |
| Протокол проверки | «В рамках тестирования было подтверждено, что в трёх синтетических сценариях бот отправил сообщение в заданное время». | «В трёх синтетических сценариях бот отправил сообщение в заданное время». |
| Речь о метриках | «Таким образом, в дальнейшем планируется проверить влияние рекомендаций на конверсию в покупку». | «Планируем проверить, меняют ли рекомендации конверсию в покупку». |

## Сверка перед выдачей

1. Проверь, что все существенные факты, числа, единицы, ссылки и условия остались на месте.
2. Проверь статус каждого вывода. «Может повысить» остаётся гипотезой. Запланированный тест остаётся планом. Результат на синтетических входах описывай вместе с этими входами.
3. Прочитай правку в контексте. В README должно быть понятно, что сделать и что увидеть. На слайде должна остаться мысль, которую можно подтвердить. В речи сохрани лексику и интонацию автора.
4. Для полного аудита покажи только находки, которые действительно мешают чтению. Работай локально в границах [CLAUDE.md](../CLAUDE.md). Стилевые замечания описывают текст, авторство по ним не определяют.
