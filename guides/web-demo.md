# Веб-интерфейс рекомендаций

Веб-интерфейс — один из вариантов показать трек 1. Его задача — провести предпринимателя от запроса до выбора материала. Постановка ранжирования и ожидаемые примеры находятся в [руководстве по рекомендациям](recommender.md).

## Экран первого сценария

1. В заголовке объясни задачу экрана. Поле «Что вы хотите сделать?» допускает запрос вроде «Запустить первую рекламу». Стадия бизнеса и желаемый формат могут уточняться по желанию.
2. Кнопка «Подобрать материалы» отправляет запрос. По ответу выведи ранжированные карточки. У каждой есть название, формат, признак платности, причина рекомендации и следующий шаг.
3. Краткое описание платной карточки и ссылка берутся только из разрешённых сведений. При отсутствии разрешённой ссылки не делай кнопку перехода. В демонстрационном режиме обозначь синтетические данные и доступные локальные действия.
4. Для показа бейзлайна добавь отдельный режим демонстрации, если он помогает оценить разницу. Подавай один профиль и один каталог в оба метода. Пользовательский сценарий должен проходить и без переключения методов.

| Состояние | Что пользователь видит |
| --- | --- |
| До запроса | Назначение экрана, поле и пример задачи. Дополнительные поля можно пропустить |
| Поиск | Понятный статус. Введённые данные сохраняются |
| Выдача | Видимый порядок материалов, краткая причина и действие по каждой карточке |
| Слабое совпадение или пустая выдача | Короткое уточнение или предложение изменить запрос. Общая подборка показывается при наличии подходящих материалов |
| Сбой | Сообщение о недоступности и возможность повторить запрос без повторного ввода |

## Реализация и оформление

Один экран можно обслуживать из существующего приложения. Отдельный клиент имеет смысл, если выбранный стек и сценарии требуют самостоятельного интерфейса. В обоих случаях алгоритм, ограничения данных и правила ранжирования живут в одном месте. Карточки отображают результат реального вызова или явно обозначенный демонстрационный ответ.

Выстрой визуальную иерархию вокруг задачи, списка и действия. На узком экране карточки читаются в одну колонку. Используй видимые подписи полей, различимый фокус и понятные сообщения о состоянии. Смысл платности, ошибки и действия должен быть понятен и по тексту. Для коротких подписей и сообщений используй [руководство по русскому тексту](russian-style.md).

## Проверка в браузере

- Открой приложение локально. Пройди путь от пустого профиля до первой карточки, затем измени профиль и сравни ожидаемый порядок.
- На узком экране проверь форму, длинное название, пояснение и кнопку. Пройди те же действия клавиатурой. Убедись, что статус и ошибки можно заметить при работе со вспомогательными технологиями.
- Проверь слабое совпадение, пустой ответ, задержку и сбой. Повтор запроса не должен очищать форму или подменять новую выдачу устаревшим ответом.
- Сверь, что закрытые данные отсутствуют и в интерфейсе, и в ответе API. Подробный перечень в [инженерной проверке](recommender-reliability.md).

Ручного прогона достаточно для первого макета. Для повторяемой проверки рабочего интерфейса при подходящем стеке можно использовать браузерный тест. Справки по HTML, доступности и Playwright собраны в [каталоге](../SOURCE_MANIFEST.md).
