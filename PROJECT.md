# Проект

## Цель

Подготовить работающий прототип для образовательной платформы малого бизнеса. Пользователь должен быстрее находить подходящий материал и понимать следующий шаг. Целевая бизнес-метрика — средняя конверсия в покупку образовательных продуктов. Дополнительная продуктовая метрика — число активных дней пользователя на платформе.

[Условие кейса](materials/case.md) — основание для требований. Руководства содержат архитектурные варианты и примеры. Статус решений хранится в [CURRENT.md](CURRENT.md).

## Два допустимых трека

| Вопрос | Трек 1. Рекомендации | Трек 2. Telegram-помощник |
| --- | --- | --- |
| Основной сценарий | Предприниматель обозначает задачу и получает ранжированную подборку с объяснениями | Предприниматель получает ответ по базе, подходящий материал и при необходимости настраивает напоминание |
| Главные входы | Каталог, профиль, история взаимодействий при наличии | База знаний, карточки материалов, сведения из диалога, параметры напоминаний |
| Что проверить без выгрузки | Логику на синтетическом каталоге и сравнение двух методов на одинаковых профилях | Поиск на синтетическом корпусе, ветки диалога, состояние и расписание. Для живого Telegram нужен тестовый токен |
| Первый риск для проверки | Каталог слабо покрывает тестовые задачи или признаки мало помогают ранжированию | Источники слабо покрывают вопросы или расписание теряет состояние при перезапуске |
| Руководство | [Рекомендации](guides/recommender.md) | [Telegram-помощник](guides/telegram.md) |

Стек свободен. Перед выбором укажи доступные материалы и доступы, границы полной демонстрации и первый проверочный эксперимент. Внутри выбранного трека сравни простой и более сложный варианты на одной постановке.

## Требования и доказательства

| ID | Требование | Что показать |
| --- | --- | --- |
| R1 | Подбор учитывает задачу, стадию, сферу, опыт и доступную историю | Профили с ожидаемыми изменениями в выдаче |
| R2 | Холодный старт и помощь при неполных сведениях | Полезный результат без истории, необязательный онбординг и сценарий без точного совпадения |
| R3 | Объяснение, следующий шаг и сравнение с простым методом | Два метода на одном каталоге и одних профилях. План оценки конверсии |
| T1 | Ответ по базе, обработка неоднозначности и пробелов | Раздельные прогоны для подтверждённого ответа, уточнения и отсутствия материала |
| T2 | Персонализация и бесплатные и платные рекомендации | Похожие вопросы при разном контексте. Для платного — краткая польза и разрешённая ссылка при наличии |
| T3 | Разовые и повторяющиеся напоминания, изменение частоты и отключение | Создание, отправка, правка и отключение. План оценки повторных посещений |
| C1 | Соблюдение ограничений по данным, ключам и платным материалам | Проверка входов, ответов, тестовых профилей и состава комплекта |
| C2 | Основной сценарий запускается по документации | Чистый запуск, инструкция Docker, результат сценария и комплект сдачи |

Для общего комплекта действуют C1–C2, для выбранной ветки — R1–R3 либо T1–T3. Шкалу и веса см. в условии. Проверки привязывай к этим ID по [руководству по оценке](guides/evaluation.md).

## Этапы и результат каждого

1. **Выбор.** Определены трек, пользовательский путь и критерий первого прогона.
2. **Входы.** Описаны фактические поля разрешённых данных или отдельно помечен синтетический контракт. Указаны пробелы в покрытии.
3. **Первый проход.** Один полный сценарий от ввода до наблюдаемого результата. Ручная проверка и ограничения записаны.
4. **Сравнение и устойчивость.** Выполнены предусмотренные треком негативные и пограничные сценарии. Для рекомендаций зафиксировано сравнение с бейзлайном.
5. **Проверка и сдача.** Запуск и демонстрационный маршрут проверены с нуля. Подготовлены материалы защиты, план измерения эффекта и проверенный список файлов.
